## 外部服务前提

协调者提供已启动服务及公开运行记录：实现 commit、完整启动命令、GPU/主机资源、固定权重路径、runtime/专家/host 预算、可执行并发和单请求 token 上限。预算由资源决定，不能按本测试未来 trace 选择。

固定模型：`/data1/yuchen/models/Qwen3.8-Flash-Next-NVFP4`。启动必须使用 `--runtime-cache-gib R --kv-placement gpu --speculative-num-steps 0`，不预先提供测试的真实并发或最终输出长度。

每个独立服务配置只运行一次完整负载，负载中不重启、不增预算、不改并发、不缩短请求。维护测试在负载完成后单独执行。协调者运行以下 16 个受支持组合并汇总，不能把单组合结果称为矩阵通过：

| 选择 | 值 |
| --- | --- |
| KV | bf16 / int8 |
| batching | legacy / layered-pipeline |

| AR Replay | 关闭 / 开启 |

## 用例与判定

1. **公开资源**：记录实际生效配置、物理预算及各组件占用。模型全部 K/V、压缩索引和每请求状态必须计价；专家容量固定。缺乏可对账的公开信息时，容量项保持未完成。
2. **历史与边界**：按检查点 tokenizer 构造实际长度为 3/4/5、63/64/65 及更长的 4/64 边界输入，覆盖多个 prefill 块。短到无法表达语义的输入用于协议/usage 边界；有完整任务的输入验证历史中的不同键值。先确认隔离执行的语义答案，再验证复用与并发后的答案。
3. **复用与换槽**：同组相同前缀分叉、同组重访、不同组隔离；交错结束不同长度请求后再提交新历史。答案不得含其他请求的值；usage 不因缓存/恢复重复计数。命中/隔离结论必须有实际缓存计数支撑。
4. **未知到达**：同进程、同预算依次提交多短、少长、再多短请求，随后混合持续到达和突发。设置较大 `max_tokens` 的早停请求，确认不会为全部输出上限占满 runtime；超过即时执行能力的请求最终继续推进。
5. **暂停与恢复**：合法小预算压力下覆盖暂停后恢复、换槽后恢复；暂停位置至少有非 4/64 对齐实例。断言答案、输出流、finish reason 和 usage；仅完成请求而没有真实暂停证据不能算该项通过。host=0 的恢复应有重算证据。
6. **取消**：取消排队者、生成者和暂停者；保留另一条共享前缀请求。取消者最终释放资源，其他请求保持正确；不再发送新流量时已有请求仍能结束。
7. **Replay 与 Graph**：生成越过公开 Replay 记录容量后再次复用；开关配置及实际执行应有证据。Graph 覆盖非满批、尾批和恢复后批次，不能以全程 eager 成功替代。
8. **维护与生命周期**：忙时 `mode=if_idle` 重建返回 busy；非法预算、旧分池字段冲突返回 rejected 且服务仍可用。空闲合法重建保留未指定的专家容量，之后重新验证历史。多轮完成/取消后，活动请求状态归零，可回收缓存不算泄漏。

失败报告保存公开请求、输出/错误、状态采样和固定运行配置。有限请求在给定超时内未完成属于本轮未通过；超时只作测试截止，不代替性能承诺。输出数值/质量的容差不得依据候选失败结果放宽。

## 运行

在有 `httpx`、`transformers` 和模型公开 tokenizer 的 Python 环境运行。脚本不会启动服务或选择 GPU；只能连接协调者提供的专用服务。不能用 `python -O` 禁用断言。

```bash
python blackbox_tests/flash_next_i3a/run.py \
  --url "$SERVICE_URL" --runtime-gib "$RUNTIME_GIB" \
  --pressure-tokens "$PRESSURE_PROMPT_TOKENS" \
  --output-limit "$OUTPUT_TOKEN_LIMIT" --copy-lines "$COPY_LINES" \
  --graph "$GRAPH_MODE" --replay "$REPLAY_MODE" \
  --report "$REPORT_JSONL"
```

`GRAPH_MODE`、`REPLAY_MODE` 为 `on` 或 `off`。其余值由协调者公布资源范围后，由测试作者冻结；当前不猜预算。压力 prompt 长度加 4 再加 output 上限必须不超过单请求 context 上限；复制任务的全部输入和输出也必须分别能放入指定长度。固定语义边界要求至少支持 1025 token 输入和 64 token 输出。

默认 `--scenario full` 执行全部已编码用例。`--scenario maintenance` 只执行取消和维护，供前段已经取得证据时续跑。维护请求尚未返回期间，既有生成入口可临时拒绝新请求；因此本用例等两条共享前缀 SSE 都已有输出，再请求 busy 重建并取消第一条，第二条必须完整正确结束。

`--scenario pause --timeout 1800` 在同一服务上追加暂停压力，不重建缓存。三条不同历史的输入长度取公开 context 上限约六成，并选为 `64n+61/62/63`；第一条已有输出后，另外两条依次到达。只有 paused 和 restored/recompute 均实际增加才报告观察到暂停恢复；单纯排队完成仍记未覆盖。`--output-limit` 和 `--copy-lines` 与前面已冻结值保持一致，`--pressure-tokens` 仍作常规运行参数记录，追加长度单独写入报告。

报告路径必须不存在，避免覆盖既有证据。记录每次请求、完整 SSE/响应、usage、状态采样、执行计数差值、失败和覆盖缺口。外部运行记录另存完整启动命令、实现 commit、GPU/主机身份与预算。

`run.py` 检查公开协议、语义答案、物理预算加总和真实执行计数；`cases.py` 只构造输入和独立预期。输出必须匹配预先写好的键值/复制任务；隔离执行失败也会停止，不能在候选失败后改答案或放宽规则。

生成接口只接收字符串。边界输入先经公开 tokenizer 构造，再解码为字符串并重新编码核对，最后断言响应 `usage.prompt_tokens` 等于预定长度。协调者首次交接把 schema 的 token-ID 类型误当成已支持输入；候选明确拒绝后已纠正契约，原 400 记录不计为生产功能失败。

运行成功只代表已编码的准备用例完成。报告仍明确写 `incomplete`，不会宣称整个 I3a 或第一阶段验收通过。以下证据必须由后续验收补齐：

- 全部模型 K/V、索引、每请求状态与实际物理分配对账，不能仅靠 status 自报加总证明没有预算外分配。
- 非 4/64 对齐暂停的公开位置证据，排队/prefill/暂停阶段取消，以及取消后的物理资源回收。
- Replay 记录容量和跨容量后的复用；仅有 flush 计数不能证明跨容量历史正确。
- 已公布最大合法单请求、host=0/正预算与 naive/公共缓存压力、16 个配置的完整运行记录。

这些材料由协调者提供或组织实际运行取得。作者不得查看实现推断接口；未执行或缺证据的项目不能报告通过。
