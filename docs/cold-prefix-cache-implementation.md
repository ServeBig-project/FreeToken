# FreeToken CPU 冷前缀缓存实现协议

日期：2026-10-05。代码基线：`e0b8383b0eb401660714d73697555e65fcff1f57`。
状态：架构与交付协议，功能尚未实现。

目标是在 FreeToken 中保存、恢复完整的可复用前缀：热数据放 GPU，值得保留的冷数据放 CPU；公共前缀管理、数据格式、搬运和保存策略分离。新策略主动删除被替代的线性历史快照，避免 GPU 和 CPU 都积累每轮 GDN 状态。

本文交给实现 agent 和协调者。独立黑盒测试 agent **只读** [公开验收契约](cold-prefix-cache-public-contract.md)，不得读本文、生产源码、diff、内部测试或实现笔记。实现 agent 不得阅读、编写或修改测试源码。

## 1 决策与交付边界

### 已确认的设计

1. 一个逻辑前缀树同时描述 GPU 和 CPU 数据；不为两层缓存各建一棵树。
2. 数据适配按缓存结构和组件能力组织，不按模型名称组织。公共管理、策略和搬运代码中不得加入模型名白名单。
3. attention KV、GDN 状态、DFlash 历史 KV 共同参与匹配。配置中启用的必需组件在同一恢复位置完整可用，才可复用该前缀。
4. 公共 GDN 缓存保存完整递推状态及卷积历史。ReplaySSM 的短记录属于活跃请求和 SD；导出公共状态时合并已接受的记录，不永久保存整条 Replay log。
5. 默认候选保存位置为最近一轮的输入侧续接点、输出侧续接点，以及观察到实际重复的公共分叉位置。所有位置必须由组件确认能够正确提取。
6. 新续接点提交成功后，主动清除同一无分叉历史链中被替代的旧快照；CPU 副本也清除。分叉候选有较高保留价值，但不是永久锁定。
7. CPU 缓存和搬运缓冲有明确字节预算；GPU 新增缓冲计入已有总显存预算。活跃请求需要的 attention KV 仍须在 GPU 上。
8. 策略有统一替换接口，供 harness 调整；数据完整性、引用归属和搬运完成条件不能由策略绕过。
9. 完成并发、取消、SD、Graph、清空及空闲重建的完整生命周期后交付，不能以单请求复制成功作为完成。

### 支持范围的确认状态

当前具体设计和必要验收覆盖已讨论的 Qwen3 与 Qwen3.6，以及主线**原本合法**的 AR、self-SD、DFlash、ReplaySSM 组合。

**尚待用户确认的唯一范围项**：滑窗及 DSV4 压缩缓存是否也必须在本轮实现并验收。此前已发出选项，不能把未回复当成选择。实现 agent 可先开展公共组件和上述已讨论链路；涉及扩大或缩小其余架构支持的实现和交付声明前，取得用户明确答复。

同结构的其他模型应复用组件，不要求增加名字适配。未经本轮覆盖的存储结构，原有功能保持可用；开启冷缓存但缺少所需组件时，启动前明确指出缺少哪种存储能力，不静默关闭功能或临时改走另一种生成算法。

本模块不包含活跃 attention KV 的逐步 CPU streaming、SSD/远端缓存、有损状态恢复、跨模型缓存复用、运行中自动重分专家/KV/GDN物理显存。释放逻辑 KV 页不等于把其预分配显存还给专家池。

## 2 改动规模与复用边界

这是缓存子系统的局部重构，加一个 CPU 存储层和异步搬运执行模块。不是全仓重写，也不是只增加几处 `copy_`。

| 当前实现 | 复用内容 | 必要改动 |
| --- | --- | --- |
| `kvcache/radix_cache.py` | token 比较、树遍历、分裂、共享路径、cache_group | 区分逻辑边界与各组件的数据位置；补充 CPU 引用，不能让树的存在依赖 GPU 页仍存活 |
| `kvcache/base.py` | handle、缓存和 pool 的公共入口 | 匹配结果从 GPU 单层扩为可恢复位置与组件集合；迁移 `cuda_handle`、`mamba_value` 等特殊接口 |
| `kvcache/hybrid_radix_cache.py` | 状态只能对应完整边界、状态与 KV 的独立引用和回收 | 将这些语义移到状态组件和公共协调流程；覆盖路径不再保留第二套匹配/恢复状态机 |
| `kvcache/mha_pool.py` 等 | GPU 实体张量、页表、现有分配器、布局与字节计价 | 提供页范围导出/恢复所需的视图和布局描述，不重写计算存储 |
| `kvcache/linear_state_pool.py` | alloc/free、copy、export、materialize、GDN 几何 | 供状态组件调用；公共快照导出不泄漏 Replay 私有表示 |
| `kvcache/gdn_replay.py` | 活跃状态恢复、有效记录、SD 提交 | 保持算法，复用正确导出边界；不能把 flush 当成公共快照保存事件 |
| `speculative/dflash_cache.py` | 跟随 target token 页的历史 KV | 注册为必需历史组件，复用分页搬运；恢复到 target 新页对应的位置 |
| `scheduler/cache.py` | 请求缓存生命周期、页/槽分配、已有锁和重建入口 | 成为公共协调入口，删除覆盖路径中散落的模型/组件特判 |
| `scheduler/prefill.py` | token 预算、排队、现有准入限制 | 增加恢复页/状态槽的预留和异步恢复等待；修正“命中后无需占 GPU 空间”的假设 |
| `engine/cache_budget.py`、状态与服务配置 | 现有预算、维护门禁、状态查询 | 计入新增缓冲和 CPU 字节，公开必要指标 |

不改模型 forward、MoE 执行、SD 接受/拒绝算法、GDN 数学或 attention kernel 来完成本模块。批量 gather/scatter 是可能需要的存储操作；优先复用现有张量操作，只有现有路径无法避免实际的复制/分配开销时增加最小搬运 kernel。

先迁移真实调用，再删除被取代的代码；不得留下“新管理器包住旧管理器，旧特殊分支仍决定行为”的双重实现。未纳入本轮的缓存结构不借机整体重写，也不为它们建未使用的适配层。

## 3 职责与依赖方向

```text
调度器
  │ match / request_restore / commit / release
  ▼
前缀管理 ──────► 保存策略
  │              选择候选位置、保留项、淘汰对象
  │              返回决定，不修改实体缓存
  ▼
缓存数据组件
  │ 解释布局与有效范围，分配所属存储，导出不可变内容
  │ 生成复制任务
  ▼
CPU/GPU 搬运执行模块
  │ 执行复制，管理自己的暂存缓冲，返回完成事件
  └────────────► 前缀管理发布可用状态或完成回收
```

建议代码落点：复用现有前缀管理与 radix 文件；新增一个组件接口模块、一个策略模块、一个搬运模块。组件实现优先放在所属 pool 附近。文件数量不是硬指标，但不得为每个模型或每个事件建立一个文件/类。

### 前缀管理拥有的内容

- token 路径、cache_group、组件引用，以及请求/搬运对这些引用的占用。
- 匹配得到的逻辑重合长度、实际可恢复长度和待恢复工作。
- 多组件的空间预留、发布与回收次序；同一份数据被多个请求需要时的共享。
- 新快照发布后触发策略清理；维护 GPU/CPU 的实际可用范围。

它不解释 GDN 矩阵、不决定 KV 张量轴、不把未完成的复制计为可用命中。

逻辑 token key 的生命周期必须独立于可回收 GPU 页。复用请求已有的 CPU token 数据描述冷前缀；不能为每个 CPU 冷节点无上限保留一份 GPU key 张量。现有热路径比较可以复用，但新增 GPU 元数据必须有容量和计价。这是需要调整的存储表示，不能只给现有 node 加一个 CPU 指针就视为完成。

### 数据组件拥有的内容

- 该组件的有效范围、物理布局、对齐要求、字节计价。
- 所属 GPU 页/状态槽的分配和释放，CPU 存储中的实体内容与逻辑单位映射。
- 从活跃计算导出已提交状态，及恢复到请求工作状态所需的操作。

CPU 分配共同受一个总字节预算约束；不为每个模型固定预留一大块 CPU 内存。复用存储结构由布局参数区分，禁止新增 `Qwen3Cache`、`Qwen36Cache` 这类按模型命名的复制实现。

### 搬运执行模块拥有的内容

- 专用 CUDA stream、完成事件、有界排队，以及固定地址的暂存缓冲。
- 对已确定源/目标范围的复制执行；必要时调用组件提供的批量 gather/scatter。

它不分配业务 KV 页或 GDN 槽，不选择淘汰项，不读取模型名称、Req 的对话内容或前缀树。源/目标生命周期由上层持有；它只拥有自己的暂存空间。

### 策略拥有的内容

仅拥有决定保存位置与淘汰顺序所需的小型 host 元数据。不得直接释放对象、操作 GPU 张量、调用 `.item()`/`.cpu()` 获取临时判断数据，或写入请求的真实缓存命中长度。

## 4 公共数据与组件契约

以下为语义接口；实现可缩短私有命名和合并只调用一次的 helper，不要求逐字生成类图。策略的三个入口与公开配置保持稳定。

### 匹配结果

匹配必须能区分：

1. `matched_length`：token 真正重合到哪里，用于发现共享边界。
2. `ready_length`：当前 GPU 上全部必需组件可直接复用到哪里。
3. `restorable_length`：考虑 CPU 上有效数据后，全部必需组件可恢复到哪里。
4. 恢复该位置需要的组件引用、缺少的 GPU 资源和复制量。

这些长度可按需推导，不要求维护三份可变计数。不能只返回 GDN 截断后的长度，否则无法发现“KV 命中更深、GDN 快照缺失”的分叉候选。

`usage.prompt_tokens_details.cached_tokens` 表示实际被复用、跳过计算的前缀长度；不能用 `matched_length` 冒充。CPU 加载回来并实际复用的前缀可计入该值，但加载等待仍计入请求耗时。

### 组件所需的最小能力

| 能力 | 输入与结果 |
| --- | --- |
| 判断覆盖 | 给定 token 范围和恢复位置，返回此组件需要哪些页/哪个边界状态，以及它们是否可用 |
| 提供可提取位置 | 给定正在执行的范围、希望保存的位置，给出当前可导出或可提前安排捕获的合法位置 |
| 计算资源 | 给定所需范围，返回增量 GPU 单位、CPU 字节；共享单位不重复收取 |
| 预留与释放 | 操作已有所属分配器；失败时能撤销本次已取得但尚未使用的资源 |
| 导出与恢复 | 导出不可变、完整内容，或恢复到已经预留的目的地；给搬运模块复制视图/任务 |
| 树分裂后归属 | 页数据按区间划分；边界状态留在原来的绝对位置，不自动生成新状态 |

不把组件接口扩为任意算子插件系统。GDN 的 `export/materialize`、DFlash 的页映射和现有 pool 字节函数是实现来源，不重写一份等价数学/计价。

实现只需要少量明确的数据记录：组件内容的逻辑范围/边界和GPU/CPU引用，恢复工作持有的资源与等待请求，以及复制任务的完成事件。GPU副本、CPU副本与“正在复制”可以同时存在，不要用单个互斥的 location 枚举丢掉这种事实。已完成副本和在途目的地必须能区分，但不需要通用事务引擎或另一套对象生命周期框架。

### 三种已讨论的数据

- **分页 KV**：保存 token 页及该组件全部必要张量。尾部只能发布已经提交、不会再覆盖的范围；未提交页尾需要写时分离或保留有效长度，不把垃圾尾部当缓存。
- **GDN 状态**：完整递推矩阵加正确位置的卷积历史；不能只复制 Replay 的旧 checkpoint，漏掉其后的有效记录。已有 `can_export` 不代表可以导出任意过去位置。
- **DFlash 历史 KV**：同样是分页数据，尽量使用同一搬运代码。保持它与 target 页的映射一致，不为同一组共享 token 页重复预留页编号；实际两份张量的字节必须分别计入。

启用哪些组件由已构造的模型/attention/state/drafter 组件注册决定。开启 DFlash 后，缺少其历史不能被宣称为完整热前缀；回到所有必需组件共同可恢复的位置再计算，不能静默改为 AR。

## 5 位置定义与 GDN 捕获

所有位置均指**模型已经消费并正式提交的 token 数**。刚采样但未送进模型的最后一个 token 没有对应状态；SD 的未接受尾部也没有公共缓存资格。

- 输入侧续接点是严格可复用的 prompt 尾部附近位置，不承诺恰好等于 HTTP 的输入长度。为计算下一 token 的 logits 可能仍须重算最后一个 token。
- 输出侧续接点是请求实际已提交状态的位置，不用“输入 token 数＋返回 token 数”粗略代替。
- 普通 KV 页对齐、GDN 可捕获边界由各组件提供；公共层不写死 64、256、32，也不从模型名猜对齐。
- 多组件取共同合法边界；向前取可用位置后，剩余 token 正常重算，不伪造中间 GDN 状态。

发现需要保留的共享边界时，必须在执行经过它之前安排捕获：复用现有 prefill 中间状态出口，或在合法位置结束一个 prefill 片段再导出。不能等整段算完后，从最终 GDN 矩阵倒推历史；也不能为每个 token 保留整矩阵来解决它。

当前 `prepare_prefill_snapshots` 跳过中间 `ChunkedReq`，主要捕获最后一段的尾部。这一点需要调整为消费“本次已选择的捕获位置”，否则策略接口虽然存在，共享分叉状态仍不会产生。优先复用现有 FLA 的提取能力，不以缩小所有请求的 prefill chunk 作为替代。

同一输入末尾出现换行合并等 token 化差异时，只按真实 token 匹配和合法边界处理。不按文本相似性复用状态，也不硬编码“忽略最后一个 token”。

## 6 保存策略接口与默认规则

```python
class PrefixCachePolicy(Protocol):
    def checkpoint_positions(self, context): ...
    def prune_after_commit(self, context): ...
    def eviction_order(self, candidates, *, tier, required_bytes): ...
```

- `checkpoint_positions` 选择组件已经声明可捕获的候选；返回位置与保存用途。
- `prune_after_commit` 返回已被新状态替代、可以删除的快照引用；不直接释放。
- `eviction_order` 从管理层提供的可淘汰对象中排序；管理层按实际回收字节执行，必要时重新收集候选。

上下文只包含已有 host 元数据：位置、父子/分叉关系、最近续接点、用途、大小、最近真实复用、所在层级和当前容量。不要为“未来可能的策略”添加模型 hidden state、router 输出、预测器或训练数据接口。

### continuation 策略

1. 将一轮的输入侧、输出侧续接点作为一组候选。已有相同位置和内容时共享，不再复制。
2. 对已观察到的 token 公共边界，如果组件状态缺失，在本次计算经过该位置时补存；第二次出现不保证马上命中，后续可受益。
3. 一轮的新续接点全部按实际完成情况发布后，清除被替代的、同一无分叉路径上的旧输入/输出状态。不要刚插入输出点就把同轮输入点误删。
4. 活跃请求及正在搬运的引用暂时不能释放；标记待回收，在最后占用者离开后回收 GPU 和 CPU 两侧。
5. 删除旧 GDN 状态不连带删除仍被更深恢复点使用的 attention/DFlash KV。
6. 分叉/显式保留点不走线性替换删除，但仍受字节预算及容量淘汰约束。命中一个深处 GDN 状态，只刷新该状态，不把所有祖先状态一起刷新为最近使用。
7. 容量淘汰优先处理已失去保留用途的状态，其余可淘汰候选按实际使用的新旧回收；不在本轮引入未经测量的 FLOP 加权公式。

不要求客户端增加 session ID。使用现有 cache_group 与 token 树关系；cache_group 是用户隔离域，不是单个会话。多个 agent 可以同组共享前缀。

**容量承诺的边界**：只有真正的无分叉追加链，旧快照才可以确定被替代。树分裂不等于永久有价值；末尾 token 差异也可能产生分裂。不能因此永久保护所有分叉，更不能宣称任意五个会话都只占十份快照。实际分叉候选由预算约束并记录复用情况，不偷偷忽略 token 差异或加入会话猜测规则。

现有显式工具快照选项开启时，捕获请求必须仍被遵守，并作为明确保留候选计数；不能因为新策略默认不额外猜工具位置就忽略用户显式配置。这些额外候选不计入“每条纯追加链最近两点”的数量示例。

### baseline 策略

复现当前保存触发和淘汰语义，用于同代码 A/B；使用相同公共管理器、组件和搬运模块。不得为 baseline 复制整套旧缓存实现。迁移后对齐原行为的实测，不直接沿用旧 benchmark 数字。

## 7 CPU 存储与资源所有权

CPU 缓存有一个总字节上限，涵盖其持有的所有组件数据。可按布局分 slab/空闲表，但不是每模型一个固定大池。必须报告已分配、有效占用和搬运期间保留的字节，避免只按有效 token 数漏算物理占用。

预算以一个 engine worker 为单位；多 rank 部署的实例 CPU 总上限是各 worker 预算之和，状态查询必须明确区分本地值与汇总值。各 rank 的组件使用原有 TP 切片和控制次序，不重复保存一份完整模型状态，不引入跨主机搬运。首轮性能数据使用单 GPU；未验收的多 rank 配置不得标为已通过，也不能以模型名或固定 GPU 编号限制公共模块。

使用有界 pinned memory 支持真正异步 DMA。分配发生在启动或受控扩充已有 slab 时，不在每个 token/每个页上反复 pin/unpin。GPU 暂存缓冲启动时分配并计价；关闭 CPU 缓存时不分配这些资源。

| 对象 | 所有者及释放条件 |
| --- | --- |
| GPU KV 页、GDN 槽 | 原所属 pool；公共引用、请求引用、复制引用都结束后释放 |
| CPU 数据块 | 数据组件调用统一预算的分配器；无保留用途且无读取/复制引用后释放 |
| 搬运暂存空间 | 搬运模块；固定容量循环复用，前一操作完成后复用 |
| 请求私有工作状态 | 原请求状态管理；公共快照不可被继续生成覆盖 |
| 公共已发布快照 | 前缀缓存共享；内容不可变，淘汰不等于修改其内容 |

新快照未成功保存时，不先删仍有用的旧快照。CPU 没空间或备份队列满时，可按策略淘汰可回收对象，或放弃这次公共备份；不迫使正在生成的请求等待仅为缓存而进行的 D2H。

当 GPU 必须回收且数据没有完成 CPU 备份时，按当前缓存未命中的语义允许丢弃可淘汰内容；不能把未完成的 CPU 副本挂为有效缓存。已经有 CPU 副本则可只撤掉 GPU 副本。

## 8 复制计划与异步执行

搬运模块只接受已经解析好的复制任务：源/目的张量范围、方向、必要的 stream 依赖和完成回调所需的工作编号。计划携带的是引用，不复制整份 token 历史或模型配置。

规范流程：

1. 组件给出要复制的真实范围和增量资源。
2. 管理层取得所需源引用及所有目标资源；某组件预留失败，撤销本次已取得的未使用资源，不留下半个可用恢复点。
3. 上层把任务提交给搬运模块，源/目标保持有效。
4. 执行完必要的 pack、DMA、scatter，记录完成事件。
5. 管理层在调度循环里非阻塞检查完成工作，再发布可用位置或解除引用。

分页存储往往不连续，不能假设一个 CPU `tensor.copy_` 就等于一次高效异步 DMA。实现应批量收集/散写，按有界块传输；禁止每 token、每页发一串 Python 循环复制。复用现有布局和张量操作可以达到要求时，不额外造 kernel。

工程起始值：每个方向一个 8 MiB 暂存块，H2D/D2H 合计 16 MiB；大对象分块，批量索引等额外 GPU 元数据也要计价。该值只是明确的实现起点，不代表最优值；作为搬运模块的局部参数供 harness 调整，不新增一组未使用的服务开关。组件已经能直接连续复制时不强制多走暂存。

前台恢复在待提交队列中优先于后台备份；后台在队列满时停止新增工作，不能无限积压。不能宣称 stream priority 可抢占已经进行的 DMA。复制与专家加载共享 PCIe/带宽，是否真正隐藏延迟须以端到端结果确认。

不得在热 decode、draft、verify 每步增加全设备同步。正常异步复制不使用 `torch.cuda.synchronize()`；维护退出阶段可在原维护边界等待自己拥有的未完成工作。

## 9 请求匹配与恢复流程

1. **匹配**：按 cache_group 和真实 token 找到重合路径，计算 GPU 已就绪位置与 GPU/CPU 共同可恢复位置。
2. **计价**：准入同时计入需要加载回来的 KV 页、请求工作状态、DFlash 存储以及剩余新输入/输出原有预留。CPU 命中只减少计算，不免除 GPU 容量要求。
3. **等待或恢复**：资源暂时不足时保留原有排队语义并让其他请求继续；不反复重新申请同一份恢复，不因等不到空间无限占着整个队列。
4. **异步复制**：共享同一 CPU 前缀的请求可以等待同一份公共恢复，避免每个请求复制一遍。恢复后各请求仍取得独立可写 GDN 工作状态。
5. **就绪**：只有所有必需组件均完成，才更新请求可复用长度、页表和工作状态。调度器只接收就绪 handle。
6. **计算**：继续普通 prefill/decode；经过事先选定边界时捕获状态。
7. **提交**：stop/EOS/SD 接受处理之后发布已提交公共数据；策略决定哪些需要备份及清理。

CPU 记录实际缺失时，使用现有可恢复的更短前缀并正常重算；不能使用 KV 命中的长度继续 GDN。硬件复制错误不伪装成正常缓存未命中，沿用服务的真实错误处理。

缓存空间无法容纳单个请求所需的活跃完整 attention KV 时，保持现有容量错误/准入行为并报告原因。本功能不能让任意长请求只把一半必要 KV 放 CPU 后仍照常生成。

## 10 部分驻留与树分裂

一个未使用的逻辑前缀可以跨 GPU 和 CPU 分段保存。GPU 的 full-attention KV 回收沿原有叶子后缀方向进行，避免主动制造“更早必需 KV 已在 CPU、后半段仍锁在 GPU”的洞。CPU 备份可以同时覆盖 GPU 热副本。

GDN 快照可以独立撤掉某个位置的 GPU 副本或整个快照；它不是对应 token KV 的所有权替代品。匹配必须在整条路径上找齐该位置需要的 attention 数据。

树分裂时：

- token 页/CPU 页按真实区间重新归属，共享物理页不重复释放；不足整页的拆分使用原有合法边界。
- GDN checkpoint 属于一个绝对位置，留在仍以该位置结束的节点；新分裂点不会自动得到 checkpoint。
- 正在执行的复制以它持有的数据范围和引用为准，不能因树节点拆分就把结果发布到错误位置。
- 删除旧 checkpoint 后，仍有 KV、其他组件数据或有效子节点的逻辑路径不因此整段消失。

## 11 SD 与 CUDA Graph

所有 drafter 共用前缀管理入口，不在 self-SD 或 DFlash 中各建 CPU cache。

- self-SD 临时 KV/状态和未接受记录不进入公共缓存。target verify 覆盖和最终提交仍由原 SD 流程完成。
- GDN 在 Replay 开/关两种表示下通过同一导出接口给出完整公共快照；关闭 Replay 时也必须支持冷缓存。
- DFlash 的历史 KV 与 target 已提交位置一致；不能把拒绝的草稿尾部发布为可复用历史。
- 请求取消、EOS、部分接受后，以真实已提交长度清理多余页/记录；保持原有正确性边界。

Graph 回放使用的模型 pool 地址和已有页表缓冲不因 CPU 恢复改变。恢复写入现有预分配 pool，更新其内容和索引，在进入计算前建立完成依赖。新增 CPU 缓存不触发逐请求重录 Graph，也不新增按前缀长度爆炸的 Graph 尺寸集合。

新增的 CPU 逻辑运行在请求到达、恢复完成、快照发布和资源回收这些边界；不要给每个 decode token 插一个策略全树扫描。策略每次只处理受影响路径和现有淘汰集合。

## 12 取消与维护

- 取消未开始的恢复：解除等待者及其预留；共享恢复还有其他等待者时继续。
- 取消已提交的复制：不假装可以取消正在运行的 DMA；完成后再释放无主目标，且不恢复已取消请求。
- 后台备份进行时，新策略决定丢弃旧快照：禁止复用源/目的内存直到该复制结束；完成后按待回收决定释放，不重新保留它。
- 清空缓存：通过已有维护门禁停止新增相关工作，处理未完成复制，清空 GPU/CPU 公共引用及策略元数据，活跃请求按原接口要求处理。
- 空闲重建 GPU 容量：先验证预算，排空传输，再由现有 pool 重建与 Graph 重录；布局和组件集合不变的 CPU 逻辑内容可保留，恢复时重新分配 GPU 页，不保存旧 GPU 指针。
- 重建被拒绝：GPU/CPU 缓存都保持原有效状态，不先清空再报告预算不足。
- 模型、dtype、布局或组件集合变化不属于可复用的同配置容量重建；沿用维护时清空相关缓存，不添加内容指纹/兼容迁移框架。

## 13 配置与可观测性

本协议采用以下明确的落地接口；名字可在开工时与已有 CLI 命名统一，但公开契约和实现必须同步，不能各自增加同义开关。

| 配置 | 默认值 | 语义 |
| --- | --- | --- |
| `--prefix-cache-host-gib` | `0` | CPU 数据层总容量，0 关闭；正值显式启用，负值启动报错 |
| `--prefix-cache-policy` | `baseline` | `baseline` 或 `continuation`，独立于 CPU 开关 |

默认值保留当前行为用于 A/B；这是工程对照设置，不宣称 baseline 最优。`host=0,policy=continuation` 可以单独评估快照策略；`host>0,policy=baseline` 可以分离搬运收益与新策略收益。两种策略共用相同模块，不提供每模型或 draft/verify 单独的缓存开关。

在现有 `/v1/cache/status` 下增加 `prefix_cache` 对象，不新增管理服务。字段与单位写入公开契约。至少包括：

- 当前策略与 CPU 是否启用；host 总预算、已分配、有效占用、在途字节。
- 搬运专用 GPU 缓冲总字节。
- GPU/CPU GDN 公共快照当前/峰值数量，活跃工作状态单独列出。
- 创建、去重、线性替换删除、容量淘汰的累计数量。
- GPU 直接复用与 CPU 恢复后复用 token 数、实际重算 token 数。
- H2D/D2H 实际字节、完成批次数、事件时间；请求等待恢复时间与公开 TTFT/总耗时分开记录。

异步事件耗时不能简单相加冒充端到端瓶颈，可能存在重叠。统计使用已有 host 决策和复制事件，不新增 token 级 GPU→CPU 同步。组件实际张量字节与状态口径必须一致；CPU 有效占用不是进程全部 RSS。

## 15 独立验收与实验方法

协调者给测试 agent 传递公开契约、可执行服务入口、模型/资源配置和允许的硬件。不得传递本文、实现源码、diff 或内部测试。实现 agent 依据公开复现条件修复；不读取黑盒测试实现。

必须完成当前合法组合下的普通 attention、GDN、Replay 开/关、self-SD、DFlash、Graph 开/关、不同 batch/尾批、不同缓存容量和用户隔离。覆盖共享前缀、中间分叉、纯追加、历史修改、并发同前缀恢复、取消和空闲重建。具体可观测条件见公开契约。

沿用已有仓库门控，失败逐项区分原有环境问题与新增问题。不要为只有文档、命名变化的可逆操作补一堆实现镜像单测。独立测试矩阵未过的配置不能称为支持。

### 四个控制组

| 组别 | CPU 缓存 | 保存策略 | 用途 |
| --- | --- | --- | --- |
| A | 关闭 | baseline | 同代码控制组，并与改动前固定提交比较 |
| B | 关闭 | continuation | 单独测减少快照的收益/重算代价 |
| C | 开启 | baseline | 单独测冷数据保存与恢复 |
| D | 开启 | continuation | 完整方案 |

固定模型、dtype、GPU、专家/KV/GDN/DFlash容量、Graph与SD配置、请求输入、输出上限及到达依赖。比较 CPU 开关时，严格配对组为关闭臂也留出同额 GPU 搬运预算余量但不分配缓冲；生产可用总预算结果另列，不能把少了 KV 的开启臂或多了 KV 的关闭臂混成纯算法比较。

至少包含三种负载：能完整留在 GPU 的热续接；工作集超过 GPU、能留在 CPU 的多会话恢复；真实历史修改/分叉。报告 TTFT、总延迟、输出吞吐、恢复字节/耗时、重算 token 和快照峰值，而不是只报缓存命中率。

先对未缩短的真实轨迹离线计算保留数量和重算分布；GPU 实验选择现有容量确实支持的原始片段。不能把 CPU 冷缓存误当活跃 KV 扩容，遇到放不下的长请求须报告；也不能无说明地裁短历史来制造收益。缩放后的 v7 数据可作为独立补充，不能替代原始分叉分布。

没有预先承诺所有负载加速。热缓存额外成本、恢复与专家搬运争用、新策略导致的重算必须分开解释。性能退化要定位，不以减少快照数量替代端到端验证。

## 16 最小实现与完成标准

实现 agent 必须遵守项目 AGENTS.md：一个模块一个职责，复用真实调用，删除未使用接口、调试代码和重复实现；不增加模型白名单、哈希、迁移框架、无调用方的通用插件体系。

完成时交付：

1. 每阶段提交、有效配置和准确支持矩阵；说明唯一范围项的最终用户答复。
2. 独立黑盒测试报告及尚未通过项，不能只报单请求冒烟。
3. 四组同条件实验和明确的策略容量/重算结论；列出未测配置。
4. 相对开工前固定生产基线的增加、删除、净增行数；测试单列，文档/生成文件/第三方代码不算生产实现。每个生产 commit 也报告行数。
5. 更新一份简短状态文档说明结论、证据入口和下一步，详细原始结果放实验目录，不往总规划追加流水账。

本轮期望“大量复用计算与实体存储，少量新增决策代码，集中新增异步生命周期”。如果需要重写模型 forward、SD 调度本体，或新增许多逐模型类，说明架构偏离本协议；先解释原因并讨论，不通过扩大代码量掩盖接口未收口。

## 17 依据与证据边界

- 本地真实轨迹：5 个 agent 会话，1,095 次请求，约10.3小时。1,090次同会话续接中，1,072次保留上一输入或只差末尾1 token，18次发生更早变化。输入长度中位数157,288，未缩放；这是输入前缀统计，不是 GPU 服务或最小容量结论。[统计证据](cold-prefix-cache-trace-evidence.json)。
- 以当前 Qwen3.6 配置，每份 GDN 公共状态约61.4 MiB；若1,095个输入尾部状态全保留约65.7 GiB。5条真正无分叉链各保留2点约0.60 GiB，但还需分叉、在用状态和其他缓存，不能将该示例作为真实总预算。
- [Marconi](https://arxiv.org/html/2411.19379v2)：在已观察的共享边界和对话末尾保存，按复用价值管理状态；包含 SWE-Agent 负载。其计算量加权淘汰不直接移植为 FreeToken 的耗时估计。
- [vLLM 实现](https://github.com/vllm-project/vllm/pull/37898)、[保留策略集成](https://github.com/vllm-project/vllm/pull/47782)：KV 命中比递推状态更深时补存共享状态；是可参考的工程机制，不是本项目已经具备的功能。
- [SGLang 状态组件](https://github.com/sgl-project/sglang/blob/df53c978f147/python/sglang/srt/mem_cache/unified_cache/components/mamba.py)：状态/页独立管理、CPU副本及路径快照回收；仅复用需要的设计，不引入整个框架。
- [Sparse Prefix Caching](https://arxiv.org/html/2605.05219)：用重合位置分布选择稀疏快照；计时主要为层组实验，不能当本服务的端到端保证。
- [SuffixReplay](https://arxiv.org/html/2609.33477v1)：用部分输入的短尾重放近似恢复，与本协议完整状态复用不同。其质量取舍及基线 CPU 状态支持差异，决定了论文倍率不能直接外推。
- [ReplaySSM](https://tridao.me/blog/2026/replayssm/)：活跃短记录和公共历史保留是不同问题；合并短记录不自动创建公共 checkpoint。
