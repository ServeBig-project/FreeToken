## 1. 交付目标与已确认决定

让 Qwen3.8-Flash-Next 使用我们现有的专家卸载、分层执行、冷热前缀缓存和真实 serving 调度。第一阶段交付普通逐 token 生成（AR）；第二阶段再接投机解码（SD）。

- 首个源权重使用yuchen本地RadixArk NVFP4。交付运行配置显式选择dense FP8、INT8 KV、tiered驻留；路由专家按源NVFP4，PLE表按源FP8驻内存。量化和驻留均可独立选择，模型类不能写死这些策略。没有磁盘按需查词表，不重新量化路由专家。
- 交付运行配置的QSA K/V为INT8＋scale，允许活跃历史页驻主机；活跃请求的压缩索引驻显存。BF16 codec和GPU-only驻留也必须可独立选择。按每请求约157000 token、多用户持续到达验收交付运行配置，不预先假定真实并发。
- 第一阶段覆盖单 GPU 文本 serving、offload／hybrid、legacy／layered-pipeline、普通 CUDA Graph／eager、AR 下的 Replay 开／关、HF源目录在加载时转dense FP8。现有模型的精度和能力保持；FTW验收暂缓。
- 图像／视频、该模型的新 TP 支持、原生 MTP、NoWAG 和其他量化格式不作为第一阶段任务；不得修改公共流程来全局禁用这些既有能力。
- 复用共享 runtime 功能的联合资源申请、弹性准入、暂停／CPU 恢复／重算。模型与 offload 可先移植，完整 serving 验收在共享池合入并通过其验收后进行；不另写一套调度器。
- 真实到达率、并发、最终输出长度未知。准入按当时状态和下一段工作计价，不依赖预先知道 trace，不按每条请求的完整 `max_tokens` 预留空间。
- 专家池仍按既有策略独立；词表是只读权重，不进入可回收请求缓存。不得借接入改变资源优先级、默认静默回退或既有模型支持范围。
- 第一阶段显式 `speculative_num_steps=0`；默认仍遵循main的AR规则。不以删除能力检查开启尚未完成的QSA SD。精度配置在转换／启动时解析，不做热路径分支；NoWAG接入保持专家provider边界，与dense和KV选项独立。

## 3. 上游移植方法

按 [移植清单](flash-next-upstream-port.md) 取文件和必要差异，不 merge 整个 upstream，也不整颗 cherry-pick `bd8f3d5`。

1. 新模型、QSA、残差混合和词表查询数学以冻结上游为参考，保留来源／许可证。去除未使用的视觉和磁盘依赖；量化取其配置／编码／方法的职责边界，复用本地算子，不整颗引入全仓重构。
2. 权重读取对接当前 `ModelSpec`、`Nvfp4ExpertSourceSpec`、`ExpertBanks`、FTW；dense复用当前FP8 W8A16算子与已有逐输出行量化方法。首次接入版本可用于旧接口适配，但后续 FTW 词表修正必须带入。
3. GDN 沿用我们的混合批次、快照、Replay 和槽 stride 实现。只增加真实需要的输出门控差异；内核本身已有 sigmoid，不从上游覆盖整份 GDN 或 FLA 元数据。
4. 复用现有专家执行与 softmax 路由。top-10 已有正确的 Torch 路径；新的融合路由若移植，必须保留 padding、重新归一化和 self-SD 的公共路由调用点。不得因 top-10 就新建模型专属专家缓存。

上游 FreeToken 自有生产代码算本功能新增生产代码；原样引入、已有第三方版权声明的算子单独列账。不能把改写的集成代码都归为第三方来隐藏代码增长。

## 4. 模型组件与权重边界

该检查点的文本结构是 48 层：36 GDN、12 QSA；hidden=2560，四路残差；512 个路由专家，每 token 选 10 个，另有共享专家。GDN 输出门控为 sigmoid。PLE 表示模型的 n-gram 查询及卷积模块，只在零基第 1 层出现；检查点 `ple_layer_ids=[2]` 是一基编号。

`models/qwen4_exp/` 持有配置、模型组装、权重命名、四路残差和 PLE 数学。新增参数放入模型专属配置对象；只把注意力组、附加状态声明等确有公共消费者的字段放进 `ModelConfig`。

量化逻辑不放进这个模型目录：模型只描述算子和权重对应关系，公共精度模块按配置／元数据／能力选择实现。指定Hub ID只是验收数据来源，不是代码分支条件。FP8／BF16、INT8／BF16、GPU／tiered的独立选择详见精度模块设计第1–2节。

模型数据流：

```text
token embedding → 复制为四路 R
每层：需要时执行 PLE → 残差混合 → GDN 或 QSA → 写回 R
                         → 残差混合 → 公共 MoE → 写回 R
末层：模型自己的最终混合 → lm_head
```

- 不继承假定 `hidden + residual + final norm` 的整套 decoder 实现。四路模型自行实现已有 layer-group 方法。
- GDN 从已有实现提取到 `layers/gated_delta.py`，成为两种模型共同调用的组件，增加 `output_gate`（旧调用明确保持 SiLU，新调用为 sigmoid）。同步改生产调用方，不留下第二份 GDN 实现或兼容空壳；内核与 Replay 数学不变。现有测试的导入更新由另一个维护者按公开入口变更处理，不能让实现者阅读或改写测试。
- MoE 复用现有 Qwen 共享专家实现及公共 `MoELayer`，`moe_router` 指向实际 softmax 组件。投影融合顺序、零中心 norm 的 `1+w`、共享专家 gate 均遵从上游数学。
- FP4专家走现有源bank、重排和offload／hybrid执行。dense大矩阵按下文转FP8；激活与四路残差仍BF16，GDN矩阵仍FP32，PLE表保持源FP8。不同对象的精度分别声明和计价。
- PLE 大表不进入 GPU `state_dict`。按数字 shard 编号组装 128 片，加载原 scale 和整数查询常量；不能按字符串 `shard_1, shard_10, shard_2` 顺序拼接。
- 词表内置的 token 哈希属于模型数学，必须保留；这不授权另加文件／行 checksum。
- 不加载 `mtp.*` 和视觉塔来服务文本。缺表片、scale、实际必需权重时报具体加载错误；不以零表成功启动。dummy 权重的零表只用于既有 dummy 路径。

### 4.1 Dense FP8：源BF16，服务驻留FP8

复用 `fp8_pertensor_linear.py` 的逐输出行FP8 E4M3 W8A16路径：`w≈q*scale[:,None]`，scale为FP32；不假装这份本地源已经有dense FP8，也不引入需要额外激活标定的W8A8。量化方法从当前GLM的 `_quant_fp8_per_row` 抽为两个模型共用的函数，逐矩阵处理并释放BF16源，不同时保留两份全模型GPU权重。

本次显式FP8 运行配置对应的dense角色包括QSA／GDN投影、共享专家投影、残差混合、PLE key/value和输出头。embedding、路由选择、norm、卷积与递推参数保持各组件原精度。这是公共策略对算子角色的选择，不在模型加载器硬编码权重路径清单；GDN的a/b投影由同一策略解析，不能继续暗定BF16。auto／bf16配置同样必须可用，不因架构名重新强制开启FP8。

按原始投影量化后，融合权重与对应scale沿输出行一同拼接。HC融合的补零行使用零权重和有效scale；不把不同投影scale取max替代。320／48／4等真实维度直接由W8A16掩码支持，不为使用128块格式大范围填充或改变数学。lm_head实现既有完整／selected输出接口，不能在每次调用时展开整份BF16权重。

FTW存储策略产出的dense和scale，记录实际方案；HF加载与FTW转换使用同一函数。FTW自包含：模型的 `ftw_side_files` 流式写入PLE side files；保留配置、tokenizer、模板和整数常量。auto重新加载不再次量化，不依赖源目录或在线补表。复用上游 `3d919e9` 的词表修正；公共精度选项是唯一选择入口，不另加模型专属环境变量或迁移框架。

## 5. 请求状态与所有权

定义位置 `p`：模型状态已经消费输入区间 `[0,p)`。它与已经发出的输出 token 数不是同一概念；沿用现有请求的模型位置和输出提交位置。

| 内容 | 所有者／索引 | 什么时候保留 |
| --- | --- | --- |
| FP8 大词表及固定权重 | 模型，所有请求共享，只读 | 服务生命周期 |
| QSA 的 K/V＋scale | QSA pool拥有逻辑页；INT8载荷可驻GPU或共享HostStore | 有效历史仍被引用时；CPU/GPU驻留可变 |
| QSA 压缩索引 | GPU索引页，每逻辑页 `page_size/4` 行，BF16 | 活跃请求计算时驻GPU；K/V迁到CPU不释放索引 |
| GDN 递推矩阵与卷积历史 | 请求状态槽 | 活跃请求或完整检查点 |
| PLE 卷积历史 | 同一请求状态槽，`[4*hidden,9]` BF16 | 与 GDN 同位置 |
| 前两个输入 token | 同一状态槽，2 个 int32，初值为模型边界 token | 与 PLE 同位置 |
| QSA 未完成组的原始 index key | 同一状态槽，12 层各 `[4,128]` BF16 | AR 活跃历史；暂停必须保存 |
| 四路残差 R 与层号 | 本批次的 layer-group state | 尚未完成所有层的计算 |
| QSA选中K/V暂存、scratch、查表输出、Graph元数据 | 执行组件 | 仅本轮选中数据与计算工作区；不恢复整段历史 |

### 5.1 附加状态沿用现有槽生命周期

采用上游 `SlotStateSpec` 的小型声明：名字、shape、dtype、初值、所属层。PLE 和 QSA pending 由各自组件声明，`LinearStatePool` 统一分配、清空、复制、`state_views()` 导出和计价。共享模式采用当前按槽集中各层的布局，扩充同一个 `Units`，取得一个槽就同时取得它的全部必要数据。

QSA pending 改为按 `linear_slot_idx` 访问，不沿用上游的 `table_idx` 所有权。页表访问仍用请求表行；两种索引在后端元数据中分别保存。恢复可以换表行、换状态槽，不能靠两者恰好相同。

普通模式也使用同一状态定义。清空／重建／取消／复制均从声明迭代，不在 scheduler 里分别写 `if qwen4`。现有无附加状态模型的存储和输出不变。

AR Replay 保留现有 GDN checkpoint＋更新记录；附加状态仍保留当前真实位置。`can_export(p)` 必须是所有必要状态都能导出的交集：GDN 能重放到过去的 `p`，不代表 PLE／QSA 历史也在。没有该位置的完整快照时不发布这个锚点，按已有合法前缀继续或重算，不能伪造命中。导出当前位置时先物化 GDN，再复制同位置的附加状态；第一阶段不为提高锚点命中另建附加状态历史环。

### 5.2 公共前缀与私有暂停快照不同

- 公共前缀沿用 64-token 页与 GDN 64-token 分块的共同完整边界。PLE 写入同一边界的 9 步卷积历史和两个 token；短尾块保留块起点时，复制起点的全部附加状态，不能从不足长的当前输入向前越界取值。
- QSA完成组的索引与逻辑页一起管理；索引在GPU时，原始K/V可留CPU。公共边界对齐4，因此其pending初值可为空；不从尚未完成全模型的层内状态发布前缀。
- 暂停按安全的整轮计算边界发生，`p` 可以不是 4 或 64 的倍数。保存到 `p` 的页、GDN、PLE、QSA pending 全部一起发布；仅其中一项复制完成不能恢复执行。
- 例如 `p=1026`，恢复后计算 1027、1028 附近的组时还要前两个未合组 index key。不能因“公共前缀都是64对齐”漏掉私有暂停状态，也不能拿压缩后的组摘要反推出原始 key。
- host不足时先回收无保护冷副本；活跃QSA历史不能直接丢弃。需要释放活跃历史时由既有暂停策略选请求，保留输入／已提交输出后重算，不再采样或重发旧输出。未完成层内波次按既有安全边界完成或丢弃后重算，不新增半层CPU快照。

### 5.3 状态只按真实计算推进

PLE 的 metadata 适配我们现有的 `FLAMetadata.decode/prefill`，不能覆盖成上游旧的扁平对象。沿现有快照 metadata 加入块边界的局部输入行，保留 `track_start_src/dst` 语义。

PLE 在其层实际执行时读取该请求之前的历史，算完后将历史推进到这段输入末端，每个真实输入只推进一次。混合批次的 decode 和 prefill 按各自序列边界处理；同请求多个 tile 按输入顺序推进。不能等整个多 tile 波次结束才统一更新历史，也不能在第一层对所有 tile 提前读同一份旧历史。

第一阶段查表在 PLE 入口用当前有效历史进行，在当前计算流完成 lookup 和消费，不保留上游跨批次的单个全局 `_pending`。保留 GPU 直接读取 pinned CPU 表的 gather 算子和稳定 Graph 输出缓冲；跨层异步预取留到有性能证据时再做，不增加相关开关。

## 6. QSA 存储与共享 runtime 接入

完整算法与接口见 [INT8与主机KV执行设计](flash-next-kv-tier-design.md)，属于第一阶段必做内容。

- 后端声明 `AttnType.QSA` 和64-token页，按能力注册，不根据模型名路由。QSA K/V采用每token、每KV head、K与V分别scale的对称INT8；压缩索引和pending保持BF16。
- QSA组件分开管理逻辑历史页、GPU索引、K/V驻留、主机副本和本轮暂存。不能沿用“申请一个逻辑页就永久映射完整GPU K/V”的价格和所有权。
- 活跃历史可以直接从主机参与下一步：GPU先完成QSA选组，只获取选中的K/V与scale，再执行attention。不等待请求暂停，不把157K历史整段搬回显存。
- HostStore沿用同一个CPU预算和引用机制；活跃主机K/V、冷前缀和暂停副本分项统计。不能把唯一有效的活跃K/V当作普通可淘汰冷副本。
- 新页、状态、GPU暂存和必要CPU空间共同通过本轮准入。资源不足交原有排队／暂停／重算机制；不增加QSA专属请求调度器。元数据不伪造GPU驻留地址。
- 保留共享池对dummy、在途保护和释放凭据的约定。只初始化已映射区域，不能复制上游整池zero；索引有效长度与K/V映射必须同时有效。

2048是稀疏选择预算，完整目标历史仍保存；INT8和主机驻留改变精度与存储位置，不能顺手裁掉未选中的历史。量化数值变化另行验收，GPU／CPU两种驻留使用同一量化字节，应得到相同计算结果。

## 7. 分层执行、Graph 与执行内存

模型实现现有 `begin/advance/finish_layer_group_*`、merge/split、范围 Graph 输入方法；`LayeredExecutionAdapter` 只操作不透明状态。状态最少为四路 `streams` 和 `next_layer`，不造没有用途的 residual 占位张量。最终输出调用模型的 hyper-connection mixer，不调用不存在的 `model.norm`。

- QSA 后端拥有页表、长度、pending 槽及索引 metadata 的构建、切分和 Graph staging。普通 AR 的混合批次每个 decode 请求一行，prefill 按真实行数拼接；不能用请求数切分多 token 输入。
- 部分层 Graph 的 replay 只执行对应层，不重复 embedding、PLE 历史更新或最终输出。纯 decode、混合批次、尾批和新请求插入使用同一位置语义。
- padding 的 token、KV 和状态写入 dummy；真实请求换槽时必须更新固定 metadata 缓冲，Graph 不能继续使用旧表行／状态槽。
- 取消尚未完成的波次，只释放真正属于该请求的未提交存储；继承 PR #7 的取消修复，不能把半完成前缀当作可共享历史。

新增且立即有两个实际调用方的适配器属性 `retained_state_bytes_per_token`：旧双张量模型报告自己的保留量，新模型报告 `4*hidden_size*dtype.itemsize`；DFlash features 另计，避免重复。Engine 的显存推导和分层波次准入共用这个值，移除 Engine 内写死的 `2*hidden_size`。

QSA执行费用不止残差：索引logits随本轮query行数和实际可见block数增长，选中的INT8 K/V＋scale另有固定上限暂存；查表、残差混合和卷积也有临时空间。后端向现有执行预算提供实际费用／分块约束，长历史不能只靠空历史两次小probe外推。GPU Graph读取稳定驻留映射和主机地址表，在图内取得选中数据，不每层把top-k结果同步回CPU。依据当前历史调整实际行数，不预测未来输出。

对所选几何，BF16 四路 R 为每 token 20 KiB；一份完整 FP32 GDN 矩阵为108 MiB，卷积及附加状态另计。这些是组件计价证据，不是让用户先猜并发的配置建议。上限只表示当前资源可执行的边界，实际准入逐轮决定。

## 8. 内存与真实 serving 规则

三个GPU账目分别清楚：固定FP8 dense权重／执行余量，独立专家池，共享runtime物理块。主机侧另计固定PLE表、专家源bank，以及同一HostStore内的活跃INT8 KV／冷前缀／暂停副本；加载临时内存另计。

用户提出约1700个dense节省槽、约570个KV节省槽，作为待核对的容量目标，不能直接写成结果。按本地头信息，本文选择的dense矩阵原始载荷减半约3.955 GiB、约1530个native NVFP4槽；131072 token的K/V转INT8且含BF16 scale约省1.488 GiB、约576槽。157000 token时另有约115 MiB GPU索引／请求，约1.811 GiB INT8 K/V可放主机；实际量还含块粒度、暂存和元数据。详见容量证据。

槽数只按真正给专家池的净字节除以实际槽价格计算。自动专家容量在启动时读取FP8实际权重费用；降低GPU K/V驻留需求后的资源方案可把余量给专家。显式runtime与专家预算不被偷偷改写；若runtime总额不变，INT8省出的空间属于runtime，不能再同时算成专家新增槽。容量A/B必须报告实际专家槽数、runtime总额、host总额和执行余量，不能只报告理论节省。

PLE 表从 header 得到实际字节，约47.7 GiB是该版本的规模参考。加载顺序为非专家权重 → PLE 表 → 专家 bank → 缓存／执行空间。现有专家串并行读取判断应看到 PLE 已占用的内存；若可用内存不能同时容纳声明的常驻数据，ready 前明确失败，不静默改成磁盘词表或收缩用户显式预算。不额外移植上游跨平台的整套 pin 配额／CPU 分层政策。

每轮沿共享池既有顺序：

1. 提交已完成输出、推进复制与取消，取得已有请求下一段可执行工作所需资源。
2. 当前资源不够，先收回无保护冷数据，再按完成顺序释放有有效主机副本的活跃K/V载荷；仍不足时由既有 `PauseManager` 让较新请求暂停，保护较早请求推进。
3. 有余量才增加 prefill tile／波次或接新请求。输入后续块、未来输出不提前全额占用；不能用小于真实需要的估价强行放行。
4. 恢复使用同一资源申请与队列。没有新流量时也继续完成复制、恢复或重算；有限合法负载最终完成／响应取消，不能相互等待永久停滞。

单请求连最小合法下一步都放不下时，沿共享池的明确容量错误处理；有限内存不承诺无限上下文。资源推导的边界不是已知负载，不新增要求用户提供“真实最大并发”的参数，也不按该参数乘系数物理预占 GDN 状态。

## 10. 第二阶段：投机解码的后续边界

本交接包直接执行I1–I5。阶段II在第一阶段最终接口与验收确定后另开实现，不提前写空接口或临时放行。总体顺序已确定，原生MTP不混入现有self-SD／DFlash任务。

| 顺序 | 必须完成的设计／接入 | 开始条件 |
| --- | --- | --- |
| II1：目标验证与状态提交 | PLE 历史、QSA pending 与 GDN 一起按每请求实际保留长度提交；拒绝后缀不可见；复用当前接受／修正采样与联合资源申请 | 第一阶段通过；以 self-SD 作为无需额外训练权重的首个调用方 |
| II2：QSA SD Graph 与 layered SD | 实现64-token页下的 verify 写入、padding、pending窗口保护及范围 Graph；按后端能力取代现有 FULL/LINEAR、FI/page1 限制 | II1 数值、拒绝尾部与生命周期通过；仅删检查不算实现 |
| II3：DFlash | 匹配的 drafter、训练时的目标特征定义、embedding／head 接口、独立窗口与前缀生命周期 | 必须先提供与此目标匹配的公开 checkpoint／特征契约；不能拿 Qwen3.6 drafter 或任意四路平均凑数 |

Replay 开启时只替代 GDN 矩阵的部分暂存，不能丢掉每个候选位置对应的 PLE／QSA 状态。草稿只使用工作状态，verify 重新计算完整目标状态，提交与模型已消费位置一致。QSA片内被拒绝的压缩组及 pending 数据必须随实际位置截断／重建，不能仅回退 KV 长度。

DFlash 已在 PR #7 独立预算，不再设计从 GDN 扣钱。目标 QSA 与 drafter 的 attention 是两个组件，不能为了 drafter 需求把目标改成 FlashInfer 全注意力。阶段 II 的可执行详细契约在开启时补齐；其 checkpoint 前置未决不阻塞第一阶段。
