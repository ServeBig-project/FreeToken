# 共享 runtime 池公开验收契约

状态：公开契约，已由独立黑盒作者据此验收（`test/runtime-pool`）。本文件只规定公开输入、输出、错误、资源与性能边界；内部设计、内核实施协议、源码、diff与实现笔记不得交给测试作者。全部验收范围完成才算feature交付。

2026-10-09接口对齐：继承已合入的SD batching与DFlash固定长度功能；不要求新增layered自适应。以下功能组合只覆盖基座公开支持的后端、attention和模型组件。

## 1. 已确认行为

目标KV、GDN状态、ReplaySSM请求记录、DFlash历史及SD临时状态共享一个runtime物理预算。专家池独立。首版覆盖全注意力目标KV及已有GDN组件与对应SD／冷缓存，没有GDN的受支持目标也可使用；包含DFlash有限窗口。目标SWA／DSV4、QSA／DSA等稀疏attention及逐轮CPU KV streaming不纳入本PR，保留其原运行路径。

服务允许请求持续到达，不需要事先提供真实并发、真实输出长度或后续 trace。实际并发、长度分布变化时，共享组件间容量可以在线转用，不通过服务重启、显式缓存重建或改变总预算实现。

首版不提供GPU自主全局分配器模式，也不增加CPU／GPU分配器选择参数。这个边界不减免物理共享、GPU计算、Graph、暂停恢复及资源开销验收；独立测试按公开结果和性能边界判断，不以内部调度代码运行在哪个设备作为通过条件。

内存压力下可以暂停活跃请求、保存到 CPU 后恢复。CPU 数据预算关闭或不足时，允许保留输入／已提交输出并重算状态；不得重新生成、重发已提交输出或重复计算用户 usage。

## 2. 公开入口

- `--runtime-cache-gib R`／Python `runtime_cache_gib`为正数，选择共享模式和每个GPU worker的runtime容量；0不是关闭方式。省略／None保留原模式，完整压力报告后再讨论默认推广。
- 共享模式与显式目标 KV 页／token 容量、GDN 独立预算／快照份额、旧分池的KV最低预留配置冲突，ready前给出可理解的错误；不悄悄转换成多个固定份额。原模式的旧参数语义保持。
- 专家显式容量不变；总 GPU 资源放不下应在 ready 前报错，不挤占专家池。
- 共享模式省略`--max-running-requests`／Python `max_running_req`时按资源／执行能力自动推导；显式值只作额外限制，两者取较小值并报告，即使显式值等于旧默认也应生效。原模式省略时保留原默认。它不是未来请求数或最快batch的承诺；提高该值不能按倍数物理预占完整GDN／Replay／draft历史。元数据和必要执行工作区可有明确的增长并报告。
- 未指定最大上下文时自动推导并公布单请求独占runtime的可执行上限；显式指定超过该能力时在启动阶段报错，不静默降低。不承诺靠暂停执行连单请求都放不下的超长历史。
- CPU冷前缀和暂停副本共用既有 host 数据预算。0允许重算路径，不分配未申报的第二个 host 数据池。
- 明确选择共享模式但硬件／组件能力不支持时报错，不能实际使用旧分池而报告共享成功。

首版覆盖文本请求以及现有TP运行路径；多模态不纳入共享模式，明确返回不支持并保留原有非共享路径。TP每卡独立物理池，请求统一暂停／恢复；不新增原本尚不支持的TP-SD。独立多GPU服务实例各自管理，不承诺跨实例全机调度。

## 3. 请求与暂停恢复

继续使用既有生成API／SSE、stop、EOS、max_tokens、cache_group、取消及超时。

- 请求身份和连接不因暂停改变；取消暂停者仍能及时终止公开请求，并最终回收资源。
- 暂停可以延长输出间隔，不等于提前完成，不伪造 finish_reason 或空成功结果。
- 首次请求计时和prompt准入不重复起算；恢复生成历史不增加该prompt的cached_tokens。原始prompt未prefill部分必须保留，不能只恢复已经处理的前缀。
- 已提交的输出序列不可因恢复改写、丢失、重复；usage只累计真实用户输入／输出，恢复计算另计。
- 恢复后的目标状态、draft历史和绝对位置一致。草稿被拒绝的尾部不成为可恢复历史。
- 重算不对已提交位置重新抽样，不重复工具调用文本。后续生成的采样参数与停止条件仍按原请求处理。
- CPU数据恢复保持存储dtype；不同执行计划的浮点差异按项目原有数值政策量化，不新增随机输出跨调度逐字一致的要求。
- 同一／不同 cache_group 的公共前缀复用与隔离保持；暂停共享前缀的一条请求不能破坏仍在运行的其他请求。

## 4. 容量和压力规则

准入只按当前已知请求／缓存和执行需求计算，不为每条请求预留完整输出上限。持续增长时可减少SD暂存、停止新准入、回收冷缓存和暂停请求；不能无限重试同一分配。

配置的prefill token额度是上限，内存不足时允许缩小实际分块／波次；已经公布为可服务的请求不得因强行执行配置最大分块而运行期OOM。不得缩短用户输入或减少其输出上限来替代资源调度。单请求连最小合法推进都无法执行时，按已有启动／长度错误契约处理。

已确认压力下优先保证最早到达的请求直到完成／取消，从较新的请求开始暂停；恢复沿用原始等待顺序，暂停不重置年龄。刚暂停者不立即换入，等待受保护请求完成／取消后再重新准入。严重压力允许逐条完成，不承诺持续过载下固定延迟；已发出的有界计算／复制仍可先到安全边界。

在公开支持的单请求长度／资源边界内，有限请求集合应最终完成或响应取消／已有明确错误，不能所有请求无限等待彼此释放空间。单请求都放不下的输入应明确拒绝／按既有长度语义处理，不能进入永久暂停。

共享预算计价包含物理块浪费、临时状态和在途保护。仅释放逻辑索引、仍不能转作另一用途，不算物理共享。可回收缓存可能暂时被计算／复制保护，统计应说明这种差别。

TP以所有worker都能执行为准，不将空闲量相加。所有worker对同一请求采用相同暂停／恢复方式和提交边界；某卡保存／恢复较慢时请求共同等待，不能挂住后续模型计算。CPU不足需要重算时整条请求采用一致恢复方式。

公共前缀缓存关闭时，私有暂停／CPU保存／重算仍可工作，不偷偷开启前缀复用。没有新请求到达也必须继续推进已有暂停请求及复制完成；不能全员暂停后永远等待新消息。

## 5. 可观测性与维护

使用现有 stats/cache status 报告：共享模式及实际预算、持有物理内存、空闲／受保护／可回收容量、各组件占用、暂停／恢复／重算数量和耗时、重算token、正常SD资源回退。虚拟寻址上限不得冒充可同时使用的物理容量。

专家池实际容量在负载变化前后保持不变。runtime 内部用途变化不要求显式维护；改变总容量沿用维护接口的明确拒绝／失败语义。暂停请求仍属未完成请求，不能被“空闲重建”误删。

单GPU的`POST /v1/cache/rebuild`在已启用共享模式时接受`runtime_cache_gib`，并继续允许显式`moe_cache_size`；未指定专家容量时保持原值。旧分池字段`num_pages`、`num_mamba_slots`、`num_swa_pages`、`swa_full_tokens_ratio`在共享模式明确拒绝，失败前后原资源仍可服务。不通过维护热切换共享／非共享模式；仍仅支持`mode=if_idle`，暂停、保存和恢复中的请求都使维护返回busy。

TP原本尚未支持的总池维护仍返回unsupported；正常TP运行的内部容量转用不得要求该维护接口。公共缓存清理不能删除仍由暂停请求持有的恢复副本。

Graph 开关、SD开关和batching策略保持独立。支持的固定配置应真实执行相应路径；不能用全程AR／eager假装SD／Graph兼容。共享本身不需要重录Graph才能完成每次类型间容量转用。

显式关闭SD不保留drafter；SD已开启但某轮因阶段／自适应／资源执行AR时，仍维护DFlash所需上下文，后续可继续真实SD。compact、native窗口、显式近似cap和非compact存储对照保持各自既有语义，不能把drafter窗口限制错误施加到目标KV。

固定SD保留legacy以及layered的outwave／inwave／all；专家后端按现有offload／hybrid能力。波次外可逐请求缩短草稿；波次内保持整批满配置窗口，否则本轮整批AR，并报告原因。自适应／observe默认关闭，只覆盖现有legacy／offload支持，显式不支持组合应拒绝；不新增波次内可变宽度策略。

普通AR保留基座的小批次Graph覆盖，显式图上限及重建后覆盖应一致；不能为通过容量验收悄悄关闭已配置的Graph。旧Graph新增保留量与SD统计字段保持已声明口径，共享物理占用须独立可辨认。

## 6. 独立验收矩阵

协调者提供合法模型、总预算、专家容量、执行上限及上下文边界。测试作者自行构造公开请求，不读取实现推断内部形状。

| 范围 | 必须验证的公开行为 |
|---|---|
| 真正共享 | 同进程同预算，多短请求→少量长请求→再次多短请求；各组件占用互补变化，专家容量不变，无重建。 |
| 未知负载 | 持续到达、突发、混合长短输入／输出、不同用户与多轮agent；改变max_tokens但实际早停，观察准入不再整段预留。 |
| 暂停恢复 | 多次CPU保存恢复，暂停前后没有重复／缺失输出；暂停期间取消，之后继续服务。 |
| CPU压力 | host为0、空间足够、逐渐填满、共享副本；不足转重算且预算不越界。 |
| 单请求与进度 | 最大合法单请求、多个接近容量请求、复制在途、非满批；有限负载持续取得用户输出进展。 |
| 功能组合 | layered/legacy、AR/self-SD/DFlash、Replay开关、Graph开关，实际执行与计数一致。 |
| DFlash内存优化 | compact开／关、有限窗口与无限历史组、cap、渐进解锁、工具锚点、复制保护；窗口优化＋layered固定SD必须组合通过，AR轮后还能SD。 |
| 后续prefill峰值 | 长历史和多轮请求中混合已有decode与新增prefill，NVFP4／hybrid、DFlash4／outwave、Replay、并发上限8及prefill上限8192的公开支持配置；资源固定，动态分块／暂停后仍完整服务。 |
| TP | 原本支持的TP模型／组件：内存压力、各worker复制就绪不同、暂停／取消／恢复、CPU不足重算；输出与进度一致，无单rank卡住。 |
| 前缀与维护 | 热／冷恢复、相同及不同cache_group、共享分叉、busy拒绝、合法空闲维护、非法预算拒绝。 |
| 公开错误 | 冲突配额、能力不支持、显式最大上下文放不下、无法容纳的固定资源；错误不伪装为成功或静默旧模式。 |
| 准入上限 | 未提供并发数自动推导，手动小／大上限均正确，公布实际值；实际负载变化无需重启改这个值。 |
| 无公共缓存／空闲 | naive模式下私有暂停恢复；没有新流量时原请求仍全部完成／响应取消，不遗留等待副本。 |

不穷举不支持的组合。TP-SD仍按既有能力决定，不因本契约新增支持要求；多模态在共享模式明确拒绝。

DFlash自适应只验已有legacy／offload组合下的容量裁剪、真实SD及暂停恢复，不把layered自适应列为前置或验收要求。策略收益和决策开销优化另行交付，当前功能正确性仍须通过。

## 7. 性能与交付边界

同 GPU／CPU／专家池／总GPU预算比较原分池和共享池，完整请求吞吐、平均／p95延迟、TTFT、TPOT、最大输出间隔与复制／重算成本分列。以连续变化的负载为主，不能每换负载重启调容量来证明适应性。

固定分池已合适的稳定负载用于检验额外开销；状态多和历史多交替的负载用于检验共享价值；CPU不足用于检验重算代价。无未经确认的固定退化百分比门槛，不能只统计decode速度或仅报通过次数。

长历史／后续prefill容量回归保持原请求集合、输入／输出上限、专家池及总GPU预算；共享模式用总预算替代旧分池硬配额，不能把冲突的旧参数原样带入。允许动态准入／分块／暂停，报告生效并发和实际SD；原分池运行失败与共享模式完成结果分别报告，不通过增加预算、删请求、截输入或关闭DFlash掩盖问题。

生产实现、独立测试作者分离。测试作者只拿本文和公开运行配置；协调者运行验收、反馈公开可复现失败。按阶段分别提交，报告生产和测试相对基线的增加／删除／净增。当前文档不代表功能已可交付。

## 8. 算子级公开验收边界

以下均使用既有生产调用入口，不新增测试专用端点。协调者提供合法模型局部维度、dtype、地址范围和调用配置；测试作者不得读取实现来寻找参数。

- `freetoken.models.qwen3_5_moe.gdn_kernels.gdn_decode_fla`：q/k为`[1,B,Hk,K]`、v为`[1,B,Hv,V]`，a/b为`[B,Hv]`；关键字A_log、dt_bias、state_source、indices、cu_seqlens、scale。state_source为`[slots,Hv,K,V]`，内层连续、槽stride可以大于紧凑布局；indices指定不同活跃槽。输出`[B,Hv,V]`并原地更新指定状态，不修改其他槽。
- 同模块`gdn_prefill_chunk_fla`：q/k/v的token维为packed总长度T，g/beta为`[1,T,Hv]`；关键字state_source、indices、cu_seqlens、scale及return_h。fresh槽先归零；输出`[T,Hv,V]`，可选返回既有chunk边界状态。不同合法槽stride不得改变数学或chunk边界位置。
- `freetoken.kernel.causal_conv1d`的varlen/decode入口：状态为`[slots,D,kernel-1]`，内层连续、槽stride可变；按提供的槽索引更新，padding不得修改真实状态。原有输入是否原地更新的契约保持；SGL和已公开的Triton路径均覆盖。
- `freetoken.kernel.triton.gdn_replay`的入口如下，合法层／行／槽stride及padding不改变结果，未选行不被修改：`gdn_replay(qkv,a,b,A_log,dt_bias,state,u,k,g,start,cu_seqlens,slots,rows,positions,scale)`；`gdn_replay_fold(state,u,k,g,start,rows,src,dst,ends,widths)`；`gdn_replay_advance(start,stats,rows,ends,widths,ring)`；`gdn_replay_conv(x,weight,window,cu_seqlens,rows,positions)`。
- `freetoken.kernel.store_cache`：指定合法行的K/V写入对应目标位置，其他行保持；indices允许该接口原有int32/int64类型。负页号、未映射地址不是合法输入，不为这些输入添加扫描或制造验收用例。

数值检查使用同一公开算子在紧凑布局与合法非紧凑槽布局上的等值输入，并覆盖prefill/decode衔接、多个不同槽、首末槽、实际padding及Graph。必要时与已有版本／独立数学参照比较；不能只检验未崩溃。容差沿用原算子契约，不因布局变化放宽。

Replay公开shape：qkv为`[T,2*Hk*K+Hv*V]`，a/b为`[T,Hv]`，state为`[slots,Hv,V,K]`；u/k/g分别为`[rows,Hv,ring,V]`、`[rows,Hk,ring,K]`、`[rows,Hv,ring]`。fold在这些存储前增加layer维；start和位置／索引按原入口整数类型。replay输出`[T,Hv,V]`并写本段记录，负记录行输出零且不写状态；有效历史＋本段长度不得超过ring。conv窗口为`[rows,W,D]`，W至少容纳conv左侧历史与本轮输入；fold/advance遵守原checkpoint位置契约。合法模型维度与dtype由协调者提供，不靠测试作者阅读源码确定。

在硬件可支持的公开预算内，必须有合法状态地址跨越32位乘法边界的覆盖；检查所选输出以及未选槽／缓冲的保护。算子级测试可以直接使用已分配且有效的张量，不构造非法指针。

算子测试不能代替服务测试：还需证明物理容量确实跨组件转用、原Graph继续执行、取消／复制／拒绝尾部无泄漏，以及单GPU和现有TP路径持续完成请求。
