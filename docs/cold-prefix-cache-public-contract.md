# FreeToken CPU 冷前缀缓存公开验收契约

日期：2026-10-05。状态：待实现功能的公开行为与独立验收要求。

本文可单独交给黑盒测试 agent。它不需要读取生产源码、内部测试、diff、实现协议或实现笔记；只能使用公开接口、已知输入输出、服务器状态及允许的性能工具。测试代码由该 agent 独立编写，功能实现 agent 不得阅读、编写或修改测试。

## 1 功能与覆盖范围

服务可将闲置、可复用的前缀数据保存在 CPU，并在之后的请求复用时恢复到 GPU，减少重复计算。它不改变请求内容或模型算法，不对状态做有损压缩。

必要验收包括 Qwen3-30B-A3B、Qwen3.6-35B-A3B、主线支持的滑窗模型（例如gpt-oss-20b）和DeepSeek-V4。用户已明确将滑窗与DSV4压缩缓存纳入本轮完整交付，不能只报告前两个模型通过。

使用现有公开合法配置；Qwen3.6覆盖ReplaySSM开/关。self-SD、DFlash、Graph的有效组合由协调者提供，不能为测试制造主线本来不支持的组合；本任务不要求额外实现原本没有的滑窗/DSV4 SD。模型名称仅用于明确测试对象，不是功能允许列表；同存储能力的其他模型不应因名称或目录不同而被拒绝。

## 2 配置与请求接口

新增公开配置：

| 参数 | 语义 |
| --- | --- |
| `--prefix-cache-host-gib 0` | 默认值，CPU 冷缓存关闭，无该功能的 pinned 数据池和 GPU 搬运缓冲 |
| `--prefix-cache-host-gib N` | N为正数，启用每个engine worker容量为N GiB的CPU数据层；多worker实例上限为各worker预算之和，不得偷偷超配 |
| `--prefix-cache-policy baseline` | 默认值，沿用原有保存/淘汰行为 |
| `--prefix-cache-policy continuation` | 优先保存最近续接位置与观察到的共享边界，主动清理被替代的线性历史状态 |

负容量、未知策略名启动时报明确配置错误。容量太小无法保存某类对象时，该对象可以不进入 CPU 缓存，服务仍保持正常生成；不能越过预算偷偷分配。

现有 `/v1/completions`、`/v1/chat/completions`、流式响应和 `cache_group` 语义保持不变。默认空组只与空组共享；不同组不能复用前缀，所有组共享总资源。

`usage.prompt_tokens_details.cached_tokens` 只计入实际复用的前缀。CPU 中找到了记录但未恢复成功，不得报成已复用。

CPU 冷缓存不扩大单请求活跃 attention KV 的 GPU 容量。协调者应给出能由当前配置正常运行的输入空间；超容量请求仍走服务原有公开行为。

## 3 状态查询

沿用 `GET /v1/cache/status`，增加 `prefix_cache` 对象。以下字段为交接约定，实现若需要改名，须先同步本公开契约与调用者，不能令测试方从源码猜字段。

```text
enabled                         CPU 缓存是否启用
policy                          baseline 或 continuation
host_budget_bytes               CPU 数据预算
host_allocated_bytes            实际分配的数据池容量，含空闲块
host_used_bytes                 有效数据和在途保留占用，不重复计共享内容
host_inflight_bytes             上项中尚有复制引用的字节，不与 used 相加
transfer_device_bytes           本功能 GPU 搬运缓冲及元数据总字节
gpu_checkpoint_count            GPU 公共 GDN 快照数量
gpu_checkpoint_peak             上项峰值
host_checkpoint_count           CPU 完整公共 GDN 快照数量
host_checkpoint_peak            上项峰值
active_state_count              请求工作状态数量，独立于公共快照
checkpoint_created              完整公共 GDN 快照创建累计次数
checkpoint_deduplicated         已有同位置状态而复用的累计次数
checkpoint_pruned               因被新续接点替代而删除的逻辑快照累计数
checkpoint_evicted              因容量淘汰的逻辑快照累计数
gpu_reused_tokens               GPU 热数据直接复用的累计 token 数
host_reused_tokens              经过 CPU 恢复后复用的累计 token 数
recomputed_tokens               缓存未覆盖部分实际执行的 prefill token 数
h2d_bytes / d2h_bytes            实际复制累计字节
h2d_batches / d2h_batches        已完成复制批次数
h2d_time_ms / d2h_time_ms        复制相关已完成工作的事件耗时
restore_wait_ms                 请求等待自身前缀恢复的累计时间
components                      各存储组件的类型、实际分配/占用及双向搬运字节
```

计数从服务启动累计；清空/重建不重置累计数和峰值，实时数量反映操作后的状态。无 GDN 时 checkpoint 及 active_state 相关字段为0。GPU与CPU数量统计物理副本，各自有同一逻辑状态的副本时均计数；pruned/evicted按逻辑状态计一次，不能把两份副本当两次策略决定。

单 worker 下以上字段即实例值。多 rank 部署必须明确标出统计是单 rank 还是实例汇总，不能把一张卡的预算当成整个实例预算；首轮单 GPU 验收不自动证明多 rank 支持通过。

`components`为数组，每项包含`name`、`storage_kind`、`device_allocated_bytes`、`host_used_bytes`、`h2d_bytes`、`d2h_bytes`。name只标识存储组件，不是模型名；类型允许paged、window、boundary_state、composite。组合存储可以分项报告，但不能把共享物理张量重复计价。GDN专有快照计数为0不代表SWA或DSV4没有缓存开销。

`gpu_reused_tokens` 与 `host_reused_tokens` 对同次请求的一段复用前缀按实际来源分段计算，不能重复计数。`recomputed_tokens` 包含本次全部未命中的新/旧输入，不包含 decode 或 SD verify；不能单凭这个字段把新增输入误判为策略引起的重算。

复制耗时可以相互重叠，不等于端到端额外耗时。查询这些字段不得触发全设备同步。host 用量不代表 Python 进程全部 RSS。

## 4 必须保持的公开行为

1. 同组重复前缀可以复用，不同组隔离。共享前缀不改变各请求自己的生成内容。
2. GPU 热前缀移到 CPU 后，同组后续请求可通过恢复继续复用；与重新计算相比，输出应保持原有数值/质量要求。
3. GDN 的恢复必须包含完整状态及其位置对应的历史；只保存一部分时不得假报命中。
4. DFlash 开启时，恢复后仍能实际起草、验证及接受草稿，不能以静默关闭 SD 获得功能“通过”。
5. 并发请求共享公共内容，但任何一个请求继续生成、取消或结束都不能改变另一个请求的历史。
6. 所有公共内容来自已接受的目标模型历史；SD 拒绝尾部不能污染后续请求。
7. 新策略下，真正无分叉的追加历史完成并且在途工作排空后，只保留最近一轮输入/输出两处所需的公共 GDN 快照，重合处共享。显式工具锚点、实际分叉及仍在使用的数据单独计数。
8. 较早快照被主动替代后，CPU 也不无限积累它们；相应 attention KV 可以继续存在。
9. 新策略不保证所有历史中间位置都命中。回到已删除的位置时可以从更早状态重算，结果仍须正确；不能为了提高命中率复用不对应的状态。
10. 任意多个会话不保证总共只有两倍会话数的快照。不同输入分叉、用户组及临时占用会影响数量，需实际报告。
11. 滑窗模型的复用必须同时满足其full-attention历史与实际需要的窗口范围；不能只恢复其中一类。窗口缺失时可以缩短复用并重算，不能假报完整命中。
12. DSV4恢复必须保留继续计算需要的压缩历史、索引、窗口和压缩器边界状态。页/压缩块边界前后的后续生成均须正确；缺少其中一项时不得报告该位置可复用。
13. 冷缓存必须按模型本来需要的数据范围存储；滑窗不强制备份所有历史原始KV，DSV4不虚构一份不存在的完整原始KV。不得通过自动修改attention算法或重新量化数据来获得通过。

## 5 独立黑盒矩阵

测试 agent 自行选择覆盖这些公开条件的输入和断言，不要求笛卡尔积穷举。

| 类别 | 公开可复现条件 | 需要观察的结果 |
| --- | --- | --- |
| 关闭回归 | host=0，baseline，与固定原版本配对 | 生成、缓存、取消与维护原有语义；新增 CPU/搬运专用分配为0 |
| 热命中 | 同组重复长输入，不制造压力 | 正确 cached_tokens，未发生无意义 CPU 往返 |
| 冷恢复 | 用其他真实请求造成 GPU 缓存压力，CPU容量足够，再访问原输入 | 出现H2D及host复用，结果正确，实际复用长度一致 |
| 共享恢复 | 多个请求同时访问同一个冷前缀 | 全部完成、无串扰；公共内容不会按等待者数量重复搬运 |
| 线性续接 | 用公开输出构造真实、严格的 token 前缀延续，多轮执行 | 旧公共状态主动减少，CPU状态不按轮次增长；排空后满足保留点规则 |
| 中间分叉 | 多个问题共享同一长输入，再复用该分叉 | 可复用点正确；没有保存到该边界时允许重算，不能伪造状态 |
| 滑窗范围 | 小于、等于、超过公开窗口大小的输入，跨窗口续接，再访问旧分叉 | 正确恢复必要范围；旧窗口缺失时诚实重算，其他仍有效的历史不被误删 |
| 滑窗共享 | 两个分叉的所需窗口部分重叠，制造压力并取消其中一个 | 另一请求仍正确，重叠内容不重复释放或无限重复保存 |
| 压缩边界 | DSV4公开配置对应的压缩块及页边界前一位置、边界、后一位置 | 冷恢复后跨边界生成正确；不把尚未完成的压缩内容计成历史 |
| 压缩状态续接 | DSV4先经历prefill、若干decode、冷缓存压力，再续接和分叉 | 压缩器/indexer继续计算正确，结果满足冷计算参考 |
| 历史修改 | 修改或移除早先输出再请求 | 命中长度不越过真实共同前缀，结果符合冷计算参考 |
| 用户隔离 | 相同文本、相同与不同cache_group | 仅同组复用，数据与输出互不污染 |
| 小容量 | 0、不足一份GDN状态、可保存数份、可容纳工作集 | 不超预算、不挂死；不够时正常淘汰/不保存/重算 |
| batch与尾部 | 单请求、多个并发、非满批，长短不同输出 | 不跨请求使用状态，尾部处理正确 |
| SD | 部分接受、零接受、提前EOS、AR与SD切换 | 无拒绝尾部污染，实际SD统计与配置相符 |
| Graph | 开关两侧，相同公开配置 | 不因恢复崩溃，不在每次命中重新录制Graph |
| 取消 | 等待恢复时、恢复期间、正常生成中取消 | 其他请求不受污染，随后空间可复用，没有累计泄漏 |
| 维护 | 当前服务支持的清空及空闲容量重建，含被拒绝重建 | 门禁/错误正确；拒绝不破坏旧缓存，成功后无旧GPU地址引用 |

输入/输出长度选择需越过实际公开支持的页和状态边界，包含非整齐尾部；不制造不存在的底层布局或调用不支持的服务模式。压力通过公开请求与容量配置产生，不直接修改内部对象。

复制自身必须无损保留存储 dtype 的值。服务级比较先固定采样、Graph与attention计划；若不同计划本来存在数值差异，量化差异并保留质量回归，不能将任意文本变化都解释成缓存误差。若暴露正式的存储操作库接口，协调者可另给其输入/输出契约进行逐值往返验收；不要求测试 agent 读取内部实现或新增仅供测试的管理端点。

## 6 性能与交付报告

比较四组：host=0/正容量 × baseline/continuation。固定相同请求、模型、专家/KV/GDN/drafter预算、Graph、SD、GPU和共享负载。严格配对时，关闭臂保留与开启臂搬运缓冲等额的预算余量，不实际分配这些缓冲。

报告实际 GPU/CPU 快照数量与峰值、分配字节、复用/重算 token、搬运字节/时间、TTFT、完整请求延迟和输出吞吐。热续接、CPU可容纳的冷工作集、历史分叉分别报告。

这是正确性和性能边界验收，不要求所有负载都加速，也不能只因快照数下降就判定性能成功。说明新增同步/复制开销、失败条件及未测项；结果可由公开请求和配置复现。

滑窗及DSV4须各有完整模型的公开服务验收与冷热性能结果。小形状存储往返可以补充，但不能替代完整模型；硬件或模型暂不可用时明确记为未完成，不能称本轮完整交付。

实现和测试各自独立提交。最终交付附相对固定生产基线的生产代码增加/删除/净增加行数，测试单列，文档及生成产物不混入生产行数。
