# DFlash 窗口存储与轻量自适应：主线实现协议

状态：设计已确认，待实现与独立验收。基线：`main@63156df`。本协议不代表功能已经交付。

交付物只有两份：本文交给实现 agent；[公开验收契约](dflash-public-contract.md)单独交给未读实现的测试 agent。测试 agent 不得阅读本文、实现源码、diff、内部测试或实现笔记。

## 1. 已确认的边界

- DFlash 在引擎总 GPU 预算中独立计价；不再从 GDN 状态预算扣钱。显式指定的专家、目标 KV、GDN 容量不变；自动容量沿用现有资源优先级求解。
- 本轮覆盖单 GPU、legacy 调度、offload 专家后端、BF16/NVFP4、Graph、并发与尾批。hybrid/layered 的实验分支不并入本轮。
- 保留现有 DFlash 的 FlashInfer、BF16 激活与 page_size=1 约束；NVFP4 指目标权重格式，不表示改变 attention/KV 格式。
- DFlash 原生滑窗的紧凑存储默认开启，不改变模型注意力数学；额外截断完整注意力历史、自适应均显式开启。
- 随生成推进，逐步解除本请求对旧公共窗口的保护；保留其他请求、显式锚点和在途复制自己的保护。必须降低实际分配容量，不能只让旧槽“理论上可淘汰”。
- 旧公共 DFlash 窗口可保存在现有 CPU 冷缓存，复用其预算、淘汰与搬运模块；命中时恢复所需窗口。
- 自适应可退 AR，但继续维护 DFlash 上下文，以便以后恢复起草。本轮不实现停止维护后再重建历史的另一种回退。
- 所有候选仍由完整目标模型验证。近似只发生在 drafter，不能近似目标 attention、GDN 或接受／修正采样。

“完整交付”包括下文全部阶段、独立黑盒和性能门槛；只完成窗口裁剪或控制器改写，不能称为完成。

## 2. 为什么要改，以及现有原型的定位

窗口原型生产提交为 `3720858`，文档/审计为 `cfa0d8e`，在 `feat/dflash-window-kv`。它是参考，不应整支不加筛选地合入 main。

已核实的动机：

| 现状 | 本次必须解决的点 |
| --- | --- |
| 原生 5 层窗口 4096、1 层全注意力，却都按目标 KV 总容量留历史 | 按层能力分组；窗口层按有界窗口池计价 |
| 原型仍为每请求保留旧前缀窗口和新生成窗口 | 渐进解锁 + 确切所有权 + 更低的物理容量下限 |
| 释放窗口使用 GPU 布尔过滤和拼接整个空闲列表 | 固定容量空闲队列，CPU 已知释放数量；不从 GPU 查询数量 |
| DFlash 依赖 self-SD 的逐专家统计和 GPU 决策 | 独立的小型 CPU 控制器，复用已有输出，不增加回传 |
| verify 按 token 均摊价格，再跨块长预测 | 按真实整轮、真实执行形状记录成本，不线性外推 |
| 近期统计衰减观测，却永久加入固定先验 | 有观测才估计，旧观测统一衰减，不制造永久低接受率 |

参考证据：同资源 NVFP4 原型中，全部限制到 4096 后 draft KV 从约 1536 MiB 降至 890 MiB；固定 GDN 容量时整卡空闲多约 604 MiB。相同执行 N8 的 A–B–A 中，旧自适应使 C4 吞吐下降约 5%–6%。前者有保守预留，后者是控制器开销，不是自适应策略天然更差。

这些是共享机器上的特定长输入结果，不是新实现的预期收益保证。详细证据保存在原型文档 `docs/dflash-performance-20260930.md`（`cfa0d8e`）及 `/data2/servebig-envs/dflash_adaptive_audit_20261008/`。本轮重新建立控制组。

## 3. 模块边界：复用什么，改什么

不新增第二套前缀树、CPU 缓存、调度器或预算管理器。

| 现有位置 | 职责与本轮修改 |
| --- | --- |
| `speculative/dflash_model.py` | 读取层的 attention 能力，执行模型数学；不决定缓存预算或淘汰 |
| DFlash 上下文组件及 `kvcache/hybrid_swa_pool.py` | 分组存储、固定映射、窗口槽分配；不判断前缀是否值得保留 |
| `kvcache/radix_cache.py` | 前缀共享、各组件引用、节点分裂、渐进解锁、复制期间所有权 |
| `scheduler/cache.py`、`scheduler/host_tier.py` | 准入、请求私有区间、复制提交/完成、取消、维护顺序 |
| `kvcache/prefix_store.py`、现有 transfer | CPU 物理内存与搬运，沿用已有实现；不另建 DFlash CPU 池 |
| `engine/cache_budget.py` 及现有重建流程 | 同一个纯字节计算用于启动、自动容量、重建和状态报告 |
| `speculative/block_cost.py` | 替换为 CPU 整块决策；不再访问 `SpeculativeCost` 私有字段 |
| 公共 SD 轮次和 Graph 组件 | 提供实际形状、现有输出、完整轮事件；保留现有 drafter/target/state 分工 |

按能力路由：目标 feature 输出、共享 embedding/输出头、目标状态回滚、attention/Graph 支持决定能否运行。禁止模型名、目录名白名单。移除 GDN 预算依赖时，还要消除 Graph 尺寸计算等路径对“不一定存在的 MoE/GDN 对象”的无条件读取；不能把一个检查删掉就宣布通用。

当前 SD 的目标支持边界未包含目标自身的 SWA；本轮复用已有一个窗口组件即可，不为未来的任意多组窗口增加通用注册框架。无 GDN 不应成为 DFlash 的人为禁止条件；真实模型支持仍取决于兼容 drafter 和已有目标组件能力。

## 4. 公开配置与 A/B

沿用 `--speculative-draft-model-path`、`--speculative-num-steps`、`--speculative-adaptive-cost`、Replay 和 Graph 参数。最多 8 个草稿 token，不含已有输入位置。

| 配置 | 语义 |
| --- | --- |
| `--dflash-compact-kv` / `--no-dflash-compact-kv` | DFlash 默认前者；后者保留全容量存储作为数学和内存 A/B。两者 attention 相同 |
| `--dflash-attention-window W` | 默认 0，不额外裁剪；正值只限制原本全注意力层的历史，原生窗口保持自身约束；保留完整当前 noise block |
| `--speculative-adaptive-cost` | DFlash 使用本协议的近期整轮控制器；不传则固定长度 |
| `--dflash-adaptive-observe-only` | 依赖 adaptive：完成一次真实初始化后，统计和算决策照常进行，但执行固定配置长度，仍按请求资源/尾部裁剪；仅用于同执行开销 A/B |

原型的 `--dflash-recent-acceptance` 不进入主线：新自适应只有修正后的近期统计，不保留旧 GPU 预测器或有偏公式作运行时回退。历史提交用于对照。

原生紧凑存储的默认值只在 DFlash 组件生效；不能因此让 AR/self-SD 启动报“不使用 DFlash 却开启 compact”。显式 DFlash 专用近似/观察参数与其他模式不兼容时，沿用配置层报错。Graph 请求不能静默改成 eager。

## 5. attention 与存储：先区分数学和容量

持久缓存保存由已提交目标 features 投影得到的 DFlash 历史 K/V；本轮 noise K/V 是临时计算，不作为公共历史。

设层 l 的历史可见上限为 `W_l`。原生有限窗口保持原值；原本无限的层在 cap>0 时使用 cap，否则无限。有限层共用窗口池，覆盖其中最大的 W；每层 attention 仍使用自己的限制。无限层按完整目标位置空间分配。没有有限层时不创建窗口池，没有无限层时不创建空的全历史张量。

- 所有位置使用原来的绝对 token 位置，不能窗口滑动后把 RoPE 位置重置为 0。
- 从历史取最后 W 个位置不等于把 noise block 裁到 W；原本双向可见的本轮候选关系保持不变。
- 额外 cap 的精确定义：设可用的已提交历史结束位置为 H（右开），原本无限层只读 `[max(0,H-cap), H)` 的历史；整个本轮 noise block 按原本可见性参与 attention。此边界以已提交历史为基准，不随同块第 j 个 mask 再右移 j。原生窗口层继续按其原始逐查询窗口定义，不套用这条近似规则。
- 存储模式不改变掩码。cap 开关才允许改变 drafter 的历史可见性。
- `--no-dflash-compact-kv` 下所有层仍按 P 留存储，但原生窗口及显式 cap 的数学照常生效；不能关闭 compact 就把 cap 静默忽略。后续分组容量公式描述 compact 路径，全容量 A/B 按实际全层张量计价。
- 为目标正式提交的有效位置追加 draft context；拒绝区间、取消区间不能发布。上下文维护仍包括实际接受的所有 token。
- 不新增每层临时 `.long()`/gather：同一组的位置映射按批次写进固定 buffer，所有同布局层复用。只在实际维度不同处分别准备。

当前 Qwen3.6 DFlash 的五个 4096 窗口层与一个无限层只是验收实例，不能写入公共逻辑。

## 6. 固定窗口槽分配器

沿用稳定的 `full_to_swa_index_mapping`，0 是无绑定。窗口数据、映射、空闲队列和 Graph 输入地址在一次服务几何配置期间固定。

空闲槽用一个 GPU 定长环形数组保存，CPU 仅保存 `head,count`。当前 legacy 调度器是唯一修改者；复制完成也由其 `poll()` 串行提交，无需另加锁、原子操作或线程。

```text
allocate(full_indices, n):             # CPU 已知 n，已完成准入
    GPU: mapping[full_indices[i]] = free[(head+i) % capacity]
    CPU: head=(head+n)%capacity; count-=n

release_live(full_indices, n):         # 全部恰好拥有一个仍有效绑定
    tail=(head+count)%capacity
    GPU: free[(tail+i)%capacity] = mapping[full_indices[i]]
         mapping[full_indices[i]] = 0
    CPU: count+=n
```

实现为两个小 kernel；索引转换在 kernel 内完成。GPU 工作 O(n)，CPU 队列操作 O(1)，与池总容量无关。无 GPU 布尔动态输出、无空闲列表拼接、无数量 `.item()`/D2H。0 和 Graph padding 均不进入可分配槽。

**不能直接把现有幂等 `free_swa(indices)` 换成上述函数。** 现有调用可能包含早已释放的窗口。必须先迁移所有权：

1. 请求私有区间记录“已分配目标页”与“仍有窗口绑定的区间”，二者不等同。
2. 公共树节点仅在窗口 live→freed 时返回其确切范围；重复淘汰不再次返回。
3. 未发布的恢复/预填充预留由计划独占，完成后转给树/请求，取消时只归还自己仍持有的部分。
4. `radix.insert/_adopt` 返回现有 `Evicted(kv, window, states)` 风格的分类范围，不能再用一个混合 Tensor 同时归还目标页与窗口。
5. speculative reject、decode reservation、无前缀模式、请求结束、prefill rewind/cancel 均取自己的 live 交集。不能把 `deferred.allocated` 全部视作仍绑定窗口。

节点分裂只划分所有权，不分配/归还物理槽。多个请求借用同一公共绑定，只增加引用。守恒关系：

```text
空闲槽 + 请求私有绑定 + 公共节点绑定 + 未发布恢复绑定 = 可用窗口容量
```

共享引用不重复计数。复制读取旧槽期间不能归还；事件依赖保证归还→复用与旧读完成的顺序。保留必要的 O(1) 准入检查，不为生产每步增加全池扫描或 GPU 完整性回传。

## 7. 渐进解锁：只解除本请求已经用不到的窗口

例：请求从公共前缀位置 P=10000 继续，W=4096。刚开始借用 `[5904,10000)`；正式推进到 T=11000 后只需借用 `[6904,10000)`，其余窗口由本请求解除保护。新生成部分存在私有区间；二者合起来仍约一个窗口，不是两个。

T 是**已提交、已经进入目标状态和 DFlash context 的输入位置数**。不是客户端已收到的输出数，也不是本轮暂定 device length。拒绝尚未处理前不能据候选位置释放旧历史。

需要保留的借用范围是 `[max(0,T-W), P)`，左端达到 P 后本请求不再保护任何公共窗口。目标全注意力的 KV 引用和 GDN checkpoint 引用保持原语义，不能一起解锁。

实现规则：

- `CacheHandle.window_ranges` 用 deque 保存旧→新的 `(tail_node, original_units, absolute_start)`，空 deque 明确表示不再持有窗口；另存下一次推进的 T。只依靠原来的 `window_uuid` 不足以处理部分解锁。
- 在已有完成/提交点推进；默认每累计 128 个已提交 token 推进一次，容量紧张时提前推进。按 token 计数，不按 forward 轮数计数。结束/取消立即释放剩余保护。
- 推进只看 deque 队首，未到边界立即停。旧 node 被 split 后仍代表尾段；若其长度已不等于记录的 original_units，用已有 `_pieces` 展开一次并反转为旧→新精确项，替换原项。消费后立即更新项与 units，不能保留大范围反复展开。每 handle 对新遇到的 split 和释放节点摊销 O(数量)，不是承诺每次调用严格只访问刚释放节点；不从根重扫祖先，也不建全局持有者索引。
- 在锁范围边界切分节点，使边界外最多只有一个释放粒度的滞留；不每 token 制造一个树节点。已发生的分叉继续使用现有 split。
- split 按现有规则把引用复制给 head、旧 node 保持 tail；边界在节点内部时只切一次，释放 head 并更新 deque 中 tail 范围。结束/取消只消费剩余 deque，删除旧 `window_uuid` 祖先循环的窗口减引用路径；普通 KV/state 解锁仍保留。不能因为“该节点引用大于零”就误减别人的引用。
- 复制计划独立持锁，请求推进不得修改复制的保护。不同请求从不同位置继续时，各释放各的范围。
- 可复用的 CPU 窗口仍在 CPU 预算内；GPU 解锁不意味着 CPU 副本同步删除。

不新增“为每个经过的窗口位置都保存一份快照”的策略。复用现有公共前缀保存策略；不让渐进解锁变成新的 CPU 备份频率放大器。

## 8. 物理容量、复制保护与准入

符号：P=目标可用 token 位置容量，C=最大活跃请求数，N=最大草稿长度，W=有限层最大历史窗口，G=128 token 解锁粒度，Q=单批允许的最大 prefill token 数。页对齐与哨兵另计。

正常生成每请求的保守上界用 `W + G + N + 1` 加现有两页安全余量，不再使用 `2W + 128*N`。同时保留批次 prefill 工作量 Q，以及有界复制预留 R。工具锚点的额外保留另计 A。

```text
p = page_size                         # 本轮 DFlash 为 1
base = round_up(W+G+N+1,p) + 2*p
R = round_up(W,p)
A = 0                               # special_token_ckpt 关闭
  或 C*round_up(W+retain_gap,p)       # 开启；现有 retain_gap=16
window_capacity = min(P, C*base + round_up(Q,p) + R + A) + 1个哨兵
```

这是统一窗口池的容量公式，不是给每请求分割互不共享的子池。若无窗口层，相关项全部为零。启动和重建使用同一公式。显式较小目标池使 `min(P,...)` 生效时，准入仍按实际可用槽限制，不能宣称保证最大并发所有长输入同时进入。

锚点上界沿用现有“每请求至多一个工具锚点及其距离过远时丢弃”的规则，不增加保存点。`retain_gap` 从同一个策略常量读取，不能复制一份 16 到预算器。锚点检查、私有窗口回收、公共解锁统一按 G 个已提交 token 推进/压力提前推进；任何一个仍按 128 次 forward 才执行，都会让 N8 的滞留超过此公式。哨兵只计一次，重叠锚点不重复分配物理槽。

R 是所有在途窗口复制合计允许占用的额外槽预算，不是“每个计划各留一个 W”。提交时按计划完整窗口范围预留信用，直到完成/取消结清，不能只扣“此刻与活跃请求不重叠的部分”：请求随后推进时重叠可能消失。重叠计划可复用已有等待任务，未复用则保守重复扣信用；合计不能超过 R。信用是预算，不重复分配同一物理绑定。

复制保护必须按真实数据组件区分：

- KV-only 复制不能顺便锁住整条路径的窗口；状态-only 复制也不能固定无关窗口。
- `busy` 继续阻止结构删除、`_adopt` 替换源页、整节点 offload 等破坏复制源归属的操作；不能简单删掉这些保护。KV-only 复制允许独立窗口回收，前提是窗口自身没有引用/复制保护。窗口复制同时保护其 full-page 身份，不能在完成前释放/重绑这份映射。
- 复用现有 KV/window/state 三类引用与计划范围，必要时增加对应复制计数；不建设任意组件注册框架。
- 计划的窗口范围先裁成真正需要的有界后缀，边界节点过长时按范围切分；只按节点数或计划个数限流不够。
- D2H 在提交前获得窗口复制额度，源槽保护到完成；H2D 在提交前取得额度和目的槽，发布后将所有权交树/等待请求。分裂时额度守恒，计划完成/取消只释放自己那份。
- 优先处理恢复；额外备份在额度不足时延后。不能先淘汰仍有价值的 CPU 数据，再发现 GPU/复制额度不足而放弃。

内存紧张时顺序：处理已完成复制→推进请求可释放范围→按原策略淘汰无保护窗口→计算本轮可行长度/准入。仍不足时缩短该请求草稿；连其必要运行窗口也不足时等待资源或按现有合法准入行为处理，不能释放受保护窗口，也不能让全部请求因一个短尾统一变成零草稿。

可选 CPU 备份不能阻塞所有活跃请求维持自己的窗口；R 的独立额度与 active 预留必须足以让已有请求继续推进。一个等待恢复的请求取消后，仍由正常完成/poll 路径结清已有复制，不丢失目的槽。空闲时也推进完成回调和状态报告。

其他请求与显式锚点会降低可淘汰量；本设计不承诺永远只占 C×W，也不承诺命中任意旧分叉。CPU 副本被淘汰后的行为沿用正确的前缀 miss/recompute，不能读已释放 GPU 位置。

## 9. 独立计价与重建

引擎预算只扣一次权重。DFlash 与目标共享的 embedding/输出头不能重复计价。DFlash 独占权重、上下文、固定 buffer、分配元数据分别报告。

```text
draft_context(P) = P * 各无限层每位置字节之和
                 + window_capacity(P) * 各有限层每位置字节之和
draft_metadata(P) = 映射 + 固定空闲队列 + 实际捕获上限所需固定描述符
total = 目标权重 + DFlash独占权重 + 专家池 + 目标KV + GDN
      + draft_context(P) + draft_metadata(P) + 其他固定buffer
      + Graph/激活的明确余量
```

`window_capacity(P)` 有封顶，不能把它折算成一个固定平均 bytes/token。自动容量沿用现有“保证 KV 保留量，再按既有优先级分专家/剩余 KV”的政策；用相同单调字节函数做整数边界求解即可，不引入优化器。

- 显式专家、KV、GDN 容量保持用户值；放不下在 ready 前明确报各项所需字节，不静默缩池。
- 省下的 draft 内存成为预算余额，自动容量按原政策使用；显式配置下允许留空，不强制塞回 GDN 或专家。
- 无 GDN 的目标不应被要求提供 `gdn_state_budget_bytes`。移除 `_draft_reserved_bytes` 一类隐藏 config 回填，使用现有预算结果的明确字段。
- CPU 副本从现有 `prefix-cache-host-gib` 支付，按物理分配计价；共享 HostSpan 不重复收费。
- Graph 可执行对象等非 PyTorch 占用不能消失在报告中。保留有界捕获尺寸，不录制每种 ragged 组合；初始化实测总占用并验证剩余运行余量。超预算在 ready 前失败，不能悄悄缩显式池。

空闲重建顺序必须保留：维护同步→poll 结清旧计划→确认无未转交的旧所有权→换资源→重置相关映射/队列→重录涉及地址的 Graph→发布新几何与统计版本。失败保留原资源或现有事务回滚语义。

仅改 MoE 池不重置仍有效的窗口映射；会清除目标页/状态缓存的重建必须同步使相关 draft 绑定失效，即便窗口物理张量大小没变。不能把旧队列带入新空树。旧版本迟到的计时不能污染新成本表。

## 10. 自适应：CPU 上决定整块长度

DFlash 路径不再开启 self-SD 的逐专家成本采集。self-SD 的 `SpeculativeCost` 保留；共享 target 执行不能因 DFlash 自适应而额外插入逐层 timing、路由 scatter/reduce 或整表回传。

每轮候选名义长度为 AR 与合法的 2/4/8，受配置上限裁剪并去重。每请求实际长度始终为：

```text
n_i = min(候选长度, 请求剩余输出约束, 该请求本轮资源上限)
```

允许同批 `[8,8,3,0]`；0 对应该请求 AR。不能取 `min(cap_i)` 再应用整批。不同候选裁剪成相同实际向量时只评估一次。

候选评估只读已有 CPU 容量/长度和 Graph 尺寸表。把物理尺寸选择抽成现有 Graph 管理器的纯 CPU 查询；不能为了给四个候选计价，先各做一次 GPU attention plan、分配临时状态或预留窗口。只为最终选择执行一次资源准备；若此时实际可行长度变化，以实际执行形状登记样本，不给原预测形状记账。

### 10.1 一轮成本的测量边界

使用 4 对预分配 CUDA events 组成小环；保存对应几何版本、实际长度、Graph 物理形状和上下文桶。

- start 在控制器决策和本轮输入准备前提交到 engine stream。
- end 在 proposal、verify、接受/修正采样、已有输出回传、CPU 提交处理、拒绝释放、必要上下文维护与回复入队后提交。
- 在**下一次原本就有的输出同步之后**收集已完成样本；空闲只做非阻塞 query，不新增 synchronize、`.cpu()` 或标量 GPU 读回。
- 一个完整样本即可初始化；不要求前后两轮恰好同 batch、同动作。
- 事件区间包括 stream 等待和 CPU 提交造成的空隙；不能再加 CPU wall、专家传输或分段时间，否则重复计价。它不包含服务排队全部时间，端到端仍另测。
- 事件环未能及时回收时跳过该次采样并计数，不阻塞生成、不覆盖未完成事件。正常 legacy 下应罕见；若持续丢样必须定位。

可保留少量 draft/verify 分段事件供报告，不能恢复逐层事件。`draft` 分段包括 proposal 概率处理、采样和候选写入；`verify forward` 与接受/纠正开销明确分列。分段只作诊断，控制器价格来自整轮。

### 10.2 接受率与预期产出

从已有 CPU 输出解包结果获得每请求真实接受数 a_i，范围 `[0,n_i]`；在 EOS/stop 截断前读取接受事实，实际交付 token 数另计。不能把 `max_tokens` 截断、取消或 stop 当作拒绝。若某样本无法区分真实接受与终止删减，跳过学习，不猜。

按实际 n_i、该请求可见上下文桶及 greedy/随机采样类别保存接受曲线。同一 key 同轮先合并再更新，避免请求顺序影响权重。不按本批最大 n 给所有请求共用曲线；改变 mask 数会改变 draft 分布。

```text
d = 2^(-距离此 key 上次观察的 decode 轮数 / 8)
A_j = d*A_j + 本次 a_i>=j 的请求数
T   = d*T   + 本次该 key 的有效请求数
S_j = A_j/T
Y(candidate) = Σ_i (1 + Σ_{j=1..n_i} S_j)
```

初始化为真实观测，无永久先验。零观测就是未知，交给探测；AR 的产出按实际可继续请求计数。计算 Y 时纳入已知输出上限；自然终止的删减不反向污染接受模型。本期不用每请求私有学习模型，避免稀疏状态和继承规则；混合任务验收若不能通过，再带证据调整设计。

### 10.3 成本表与选择

用标准有界 `dict/OrderedDict`，成本表与接受表分别至多 1024 项，记录中为固定小数组。不要自写哈希表。每轮只访问最多四个候选，不能遍历所有专家、前缀节点或整个成本表。

成本 key 包括：batch 大小、按 greedy/随机采样分组的实际长度直方图、真实位置数、draft/verify Graph 物理位置数、目标与 drafter 的可见上下文工作量桶。已知形状等价且实际长度向量等价的名义候选合并，不只凭最大草稿长归类。

上下文桶以已有 CPU 长度计算：累计“查询位置数×该层组可见历史长度”，按 2 的幂分桶，区分目标与 draft 工作量；它只用于归类，不用于线性外推时间。层组及其系数在初始化汇总，不每轮扫描模型层。接受曲线用每请求可见历史长度桶，不能遍历 GPU 元数据来求桶。

成本维护衰减时间和权重：`Csum=d*Csum+round_ms; weight=d*weight+1; cost=Csum/weight`。估计分数为 `cost/Y`，表示每个有效输出 token 的整轮成本。AR 必须包含 DFlash context upkeep；不能拿卸载 drafter 的纯 AR 时间作为它的内部价格。

不同宽度、batch、物理 shape 或明显不同上下文不按 token 数乘倍率补价。未知 key 保持未知；合法 incumbent（当前采用的名义长度）仍可按每请求裁剪执行并采样。新尾批不因一个短请求把其他请求缩为 AR；同样不能假装见过一次 N8 就已标定所有并发/尾批 N8。

### 10.4 初始化、探测和回退

以下常量是首个实现的内部策略参数，必须经过性能门槛，不是论文保证；不新增一排 CLI 调参项。

- 一次服务几何版本首次出现可持续 decode 时，以真实请求执行一次 AR，再对可行 2/4/8 各做至多一次初始化观察；请求太短则自然延期。初始化开销单列。每个新 context/ragged key 不重新享有免费初始化。
- 新 key 沿用当前合法名义长度并按请求裁剪，收集它自己的时间；没有 incumbent 时用 AR。不能以不存在的其他形状价格做正式切换。
- 正常执行按实测整轮时间积累 3% 的探测额度；通常间隔至少 16 轮再探测。额度有上限，至多保存当前合法候选中最大预留费用的两倍（包括下条对未知候选的保守预留），避免空闲攒出突发长探测，也避免上限小于未知候选门槛而永远无法探测。
- 已知候选按最近实测整轮费用预留；未知候选用最近真实轮成本乘 `(N+1)` 作保守预留，仅作为探测预算，不作为收益预测。执行后按实际费用结算，超支成为负额度，由后续正常轮补回。
- 探测在当前合法候选中轮转，包含 AR；低接受退 AR 后也保留有限探测恢复 SD。只运行真实请求，不额外合成 forward。
- 非探测轮比较已有有效证据的动作对，未知候选不能否决其他两个已知候选之间的切换。进入 SD 或更换 SD 长度要求约 5% 预计改善；已有 AR 对照时，当前 SD 连续两次观测的预计优势不足 2% 就退 AR，避免探测成本吃掉微小收益。近期窗口之外（建议 128 个 decode 轮未刷新）的价格视为过期，等待受预算约束的刷新。
- 拒绝、取消、重建和自然尾批分别计原因；容量裁剪与成本选择不可混成一个“自适应选择短草稿”指标。

观察模式的真实初始化与普通自适应相同，完成后才固定执行 N；建议与实执行分开记。时间、接受、样本和探测花费只归实际动作，不能把建议的 AR/N2 记成已测。其后建议探测但未执行不扣探测额度，也不刷新被建议动作的证据。即使探测条件满足，也应继续计算已知动作分数，而不是反复在“应该探测”分支提前返回。正式同执行 A/B 按负载分别热身，在相同 batch/context 范围完成初始化后计分；报告实际进行了候选费用比较的轮数及每轮有效候选数量，不能拿“全是未知、立即早退”或仅给 N8 自身打分的低开销冒充达标。

复杂度目标：每轮 `O(候选数×batch + batch×Nmax)` CPU 工作，Nmax≤8；不随专家数、GPU 池容量、历史 token 总数线性增长。固定模式不构建控制器的 GPU 数据或运行选择逻辑。

## 11. Graph 与量化的必要正确性

- 固定数据、映射和输入 buffer 地址；变长通过已有逻辑长度、物理捕获尺寸和遮罩表达，不为每个长度向量录一个 Graph。
- 控制器在 CPU 选择一次整块，不逐 token 发起决策；metadata 用固定缓冲更新。
- 原型已发现 NVFP4 padded expert slot=-1 被 kernel 当真实权重地址读取。迁移时同时修复实际使用的 marlin/serial 路径：无效行在读权重之前退出并写确定输出。不能用跳过测试或降低 N8/C4 支持范围处理。
- BF16 与 NVFP4 target 均保持自己的 AR/SD Graph 对照；DFlash 权重/激活仍按其公开支持格式执行，不声称目标 FP4 等于 drafter FP4。
- Graph 填充位置不得分配公共状态、写公共上下文或进入接受统计。Graph/eager 的浮点差异需量化并做质量回归，不能以逐字不同直接认定状态错，也不能以“浮点误差”掩盖可复现污染。

## 12. 统计：够验收，不在热路径造报表

`/v1/cache/status.geometry.dflash` 保留原字段，并明确拆分：`weight_bytes` 为独占权重；`context_bytes = full_context_bytes + window_context_bytes`；`metadata_bytes` 包含映射/队列/固定描述符；`workspace_bytes` 为其他固定工作区；`reserved_bytes` 为以上四个不重叠大项之和。window 总槽/空闲/受请求保护/受复制保护及 CPU 物理字节可以在状态查询时汇总。字段有交集的保护数要说明，不能把重复引用相加当物理占用。

`/v1/stats` 保留现有累计计数，补足以下可观测量：实际草稿长度分布、按形状的真实/物理 verify 位置、accepted 与最终 emitted、固定/成本选择/探测/资源裁剪次数、完整轮和 proposal/verify 累计时间、控制器 CPU 决策时间、采样丢弃数、探测实耗、初始化实耗。

不逐 token 输出日志，不在每轮序列化整表。兼容现有核心统计字段；旧 `dflash_block_gpu_ms` 若口径扩为完整 proposal，明确 `timing_scope`，不可和历史仅模型 forward 数字直接拼表。预算与状态的完整 byte breakdown 在启动/重建/状态查询计算，不每层计算。

基线始终记录 main `63156df`；实施期间若 rebase，保留原始基线和新基线映射，不复用旧跑分。

| 阶段 | 生产提交内容 | 必须独立验证的公开行为 |

| 1 | 量化 Graph 必要修复、按能力分组、独立预算和默认值 | BF16/NVFP4、原生数学 A/B、无 GDN 预算依赖、非法容量 |
| 2 | 确切所有权与定长窗口分配器 | 分配回收/环绕、拒绝/取消、共享前缀、重建守恒 |
| 3 | 渐进解锁、按组件复制保护、降低实际容量 | 长生成、分叉、复制中 split、冷恢复、压力准入和物理省内存 |
| 4 | 整轮 CPU 控制器及公开计数/观察模式 | 固定/自适应/同执行对照、ragged、EOS、退 AR 再恢复 |
| 5 | 跨模块精简、文档和完整矩阵收尾 | 全矩阵与性能门槛，明确未覆盖项，不制造“全部通过” |

一个阶段一个生产 commit；测试由另一个未读实现的 agent 按阶段独立提交。实现者只改生产代码/构建/公开接口，不新增、阅读或修改测试。协调者传递公开契约、运行测试、转述公开失败。实现 agent 不能通过读黑盒源码来适配测试。

每个 commit 报生产增加/删除/净增；测试、文档、生成产物、第三方代码分开。先删重复的旧 DFlash 预测与临时兼容逻辑，再做模块拆分；不保留没人调用的策略接口或抽象类。模块界面以本轮两个真实消费者/布局需要为限。

最终验收必须同时满足：

1. 公开契约矩阵通过，现有 AR/self-SD 未因共享缓存改动退化；支持边界未被悄悄缩小。
2. 实际窗口容量不再包含每请求固定双窗口；启动/重建/状态字节一致，CPU/Graph/负载峰值完整报告。
3. 同实际执行 A–B–A 中，控制器端到端额外开销目标≤2%，决策 CPU p95≤50 μs；控制组漂移超过待判断效应时结论为未确定。
4. 稳定低接受场景，计入探测后的自适应稳态时间损失相对“保持上下文的 AR”目标≤5%；初始化和纯 AR 另列。高收益场景必须实际恢复 SD，不能靠永远 AR 通过。
5. 短/长上下文、C1/C4/C16、真实 coding/research 多轮请求上，与固定 N2/4/8 和纯 AR 同资源对照。逐项报告，不要求不可能的“总比事后最优策略更快”。验收负载集合预先固定，不能看到结果后删除失败负载。

以上是验收目标，不是已实现效果。失败须定位并修复或向用户说明实际取舍，不能偷偷放宽阈值、改池容量、换更短输入或把 eager 当 Graph。没有独立验收与性能证据，保持“待交付”。
