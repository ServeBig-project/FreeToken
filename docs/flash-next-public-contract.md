## 3. 入口与配置语义

沿用 `ft serve --model <dir>`、Python `LLM`、文本HTTP和维护接口。新增公共精度／驻留选项，不新增“Flash-Next模式”、磁盘词表或要求真实并发的参数：

- `--dense-quant auto|bf16|fp8`／`dense_quantization`，默认auto；auto按源方案，bf16显式使用或解码到BF16，fp8显式FP8。不能按模型名／目录自动强制fp8。
- `--kv-dtype auto|bf16|int8`／`kv_dtype`，默认auto保持后端既有格式；显式选择按实际codec能力校验。
- `--kv-placement gpu|tiered`／`kv_placement`，默认gpu；tiered允许活跃K/V驻主机，实际位置由资源决定。
- tiered要求正值 `--runtime-cache-gib` 和 `--prefix-cache-host-gib`，缺少任一预算时在ready前明确报错。只在申请不足时按冷数据、已备份活跃K/V、暂停的顺序回收。
- 既有专家选择／`--nowag-expert-path`保持独立。关闭dense额外量化不改变专家方案；bf16展开量化权重不等于找回原始未量化数值。
- 选项在转换／启动解析，本轮不热切换精度；页在CPU/GPU间迁移不要求重启。既有模型不传新选项时保持原行为。

运行模板（占位符由协调者按硬件替换；命令在实现完成后执行）：

```bash
ft serve --model /models/flash-next-nvfp4 \
  --moe-backend offload --batching-policy layered-pipeline \
  --dense-quant fp8 --kv-dtype int8 --kv-placement tiered \
  --runtime-cache-gib R --prefix-cache-host-gib H \
  --speculative-num-steps 0
```

模板故意不填写未来真实并发或输出长度；`R/H` 是容量，不是负载预测。hybrid替换既有后端选项；Graph关闭使用既有 `--cuda-graph-max-bs 0`。可使用显式执行上限做对照，但它只限制服务，不能作为未知负载主验收的前提。

- `--runtime-cache-gib` 的冲突参数、自动推导能力、物理预算和维护语义沿用共享池已交付契约。新模型必须接入同一机制。
- 未显式指定并发时根据资源和执行能力确定可执行边界；请求实际到达超过同时执行能力时排队，不需要重启改并发数。
- 输入长度已知；最终输出未知。`max_tokens` 是请求终止上限，不是准入时为其完整预留历史的要求。
- 词表在ready前加载为所有请求共享的常驻数据；请求变多或前缀被淘汰不重复加载整张表。主机空间不足时明确启动失败，不偷偷变成磁盘模式或其他量化。
- FTW转换扩展同一个dense选择：`ft checkpoint --model <source> --out <target> --dtype bfloat16 --moe-backend offload --dense-quant fp8`。保存实际FP8与scale；服务auto按产物声明，不再次量化或依赖转换机环境。源目录隔离后仍可启动，词表／模板完整。
- Host预算H在tiered模式中覆盖活跃K/V、冷前缀与暂停副本，分别可观测；PLE和专家源权重另计。0预算不能偷偷另分CPU池，也不能声称主机KV已生效。
- 关闭FP8、INT8或tiered后按实际资源重新报告可执行范围；容量不够应明确处理，不能暗中重新打开被关闭的项。

### 精度的公开数学

FP8 运行配置对非路由dense投影与输出头采用E4M3、每输出行FP32 scale、BF16激活。embedding、路由、norm、卷积和递推参数保持其原组件精度。融合投影保留每行对应scale；不是全部非专家张量无差别转FP8。

INT8对每token每KV head的K、V分别取scale：非零向量 `s=BF16(max(abs(x))/127)`，全零使用1；按最终存储的s做最近偶数舍入并截到[-127,127]，读取为q乘s。QSA压缩索引和pending仍BF16。GPU／CPU存同一编码，迁移不能重复量化或丢scale。

## 4. 正确生成与协议

保留既有stream／非stream、temperature／top-k／top-p、stop、EOS、max_tokens、usage、cache_group、取消、thinking和工具调用文本协议。不同API适配层保持各自既有支持范围，不要求本任务新增未有的参数语义。

- 单请求完整输入与分块输入、前缀未命中／热命中／冷恢复、普通运行／暂停恢复，均表示相同输入历史；不能遗漏历史、跨请求污染或重复输出。
- 模型处理位置与已发出的输出位置可能相差一个待消费token；暂停恢复不能重复采样或遗漏这个token。
- 取消在队列中、prefill中、decode中或CPU复制等待中均最终结束并释放自身资源。取消一个共享前缀请求不影响另一个请求。
- 共享前缀遵守cache_group隔离；相同前缀的不同续写不会串内容。工具调用锚点、对话继续、reasoning参数使用检查点模板及原服务语义。
- 关闭公共前缀缓存不取消私有暂停／恢复能力。CPU历史预算为0时仍能通过重算继续，已发SSE与usage不重复。

测试作者独立构造公开模型支持的短输入、小规模合法模型／算子配置，核对token embedding、词表查询及历史、四路残差混合、GDN输出gate、QSA选组与输出、专家组合。小模型数学不替代真实权重服务。

分别验证：相同量化权重／KV编码的算子与驻留一致性，以及dense FP8／INT8 KV相对关闭配置的质量变化。源检查点既有成绩不为新增量化背书。HF经相同策略转换与FTW直接加载、同批次和历史的执行应一致；不同批次／Graph／切块的近似平局差异须有数值与质量证据，不豁免重复、乱码或稳定错误。

| --- | --- | --- |
| 分组与块边界 | 短输入；长度在4和64倍数前后；跨多个prefill块；短于历史窗口的尾块 | 分块与连续计算对应同一历史，后续请求无污染 |

| 活跃主机KV | 请求未暂停时GPU索引仍在、部分或大量K/V驻CPU，持续生成 | 只取得选中数据；不能整段恢复历史到GPU或全程偷偷保持全GPU |
| 157K多用户 | 同进程固定预算、多个约157000 token已处理历史，持续加入不同长短请求 | 预算足够时多个长历史同时存在且输出交错推进；超容量时准入／暂停，不假设真实最大并发 |
| 批次 | 单请求、不同非满批、短请求插入长请求、持续到达与突发、不同完成时间 | 无需预知实际并发，尾批正常，排队后能推进 |

| 热／冷前缀 | 同前缀分叉、长短前缀、host满后淘汰、再次访问、不同cache_group | 命中和重算语义正确；缓存命中计数不伪造 |

| CPU不足 | host=0、小预算、从可保存变为不足；取消等待复制者 | 正确转重算或排队，不增设未计价CPU池，不永久等待 |

## 7. 可观测性与错误

复用 `/v1/cache/status`、`/v1/stats` 和现有日志：requested／effective精度与驻留、实际dense字节、GPU K/V载荷／索引、活跃主机K/V／冷副本／暂停副本、稀疏读取字节、实际专家槽数、runtime物理容量、暂停／恢复／重算和Graph执行可区分。词表作为固定主机权重报告一次；不能把虚拟容量当实际占用或把同一副本重复计价。

`/v1/cache/status` 的 `prefix_cache.runtime.kv_host_read_bytes` 累计服务启动以来读取的选中主机K/V及scale逻辑字节，不含PCIe协议开销。统计异步更新，允许落后一次采样。同一 `runtime` 对象内的 `kv_host_payload_pages`／`kv_gpu_payload_pages` 是保留的逻辑页数，可能含冷缓存，不能仅凭它们证明活跃attention读取了主机历史。

同一 `runtime` 对象的 `host_active_kv_bytes`、`host_paused_bytes`、`host_cold_bytes` 按归属拆分主机数据，每个字节只计一次：请求仍持有的页的K/V与scale主机副本；暂停请求持有且不属于前者的副本；其余为冷数据，即前缀副本、无人持有的页和在途复制，取 `host_used_bytes` 减去前两者。暂停请求在保存复制完成、释放显存页之前，其字节仍计入活跃。

复制仍在途时允许资源继续受保护；完成后必须能回收。仅槽号释放而实际容量永远不能重新使用不算通过。通过持续负载验证进度；没有新请求到达时也必须完成已有恢复和取消。

公开错误至少覆盖：缺失词表分片／scale、词表无法驻留、非法共享预算或冲突旧配额、显式选择未支持的attention／SD／TP或请求类型、超过公布单请求可执行范围。沿现有错误通道给出可理解原因，不增加专用测试端点。

## 8. 性能、回归与完成判定
